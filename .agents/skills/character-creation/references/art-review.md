# 静态插画制作与视觉验收

先看本卡原图与游戏中的实际裁切。角色只有一张静态插画，取景与焦点决定它在手牌、场上、详情和图鉴里的表现。

## 素材决策

- 完整头身构图；主体居中偏上，让 `focus` 能在 336×448 的卡窗里取到脸部与上半身。
- 脸、体型、装备、主色与姿态应能直接认成同一角色。替换既有原画前先取得用户确认。
- 神祇、契兽与英雄 portraitId 使用 768×1024，普通卡 336×448；不要用别人的插画补缺。
- 不承诺未制作的表情或姿态变体。单张插画就是全部交付，没有任何逐帧动画层。

可用的图像请求结构：本角色原图为身份参考；说明画面内容与取景；列出不得改变的面部/服装特征。保留实际请求全文和原始输出。历史提示词可读 `assets/anime/*-sources/` 下的 provenance 记录，但不要机械复制历史失败素材的剪裁值。

检查 alpha 与边缘本身，而不是肉眼看到棋盘就认为透明。对白毛、肤色、嘴腔、牙齿、火焰逐处检查：遮罩可能把角色内部误认成孔洞。白毛、雪和眼睛高光不能当背景一起抹掉。原图像素不能用“全删近白色”这类规则粗暴抠空。

## 两个尺度验收

1. **场上真实尺寸**：随从卡窗很小，主体必须仍可辨认；检查 `focus` 是否把脸切出画面。
2. **放大尺度**：在卡牌详情与图鉴里检查白边、透明孔洞、伪文字和压缩噪点。
3. **交互**：手牌 hover/click、出牌、变形、死亡与视口旋转没有残留或空白画面。
4. **资源**：`assets/anime/manifest.json` 的哈希与运行 WebP 一致，`assets/characters.json` 的 ID 集合与它完全相等；实际测试工具在仓库，不另造一份 skill 专用渲染器。

不合格时修复具体素材或 `focus`。取景要通过游戏尺寸观察确定，不能只看放大图就宣称“已可见”。
