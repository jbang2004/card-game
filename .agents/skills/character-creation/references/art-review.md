# 分层制作与视觉验收

先看本卡原图与游戏中的实际裁切。决定哪些部件需要独立运动，而不是先套用三层格式再想动作。

## 素材决策

- 完整头身通常比切下头部再粘回去稳妥。需要歪头时，头层必须带足够颈部重叠，身体层补齐遮挡；不能用错位或缩放掩盖断颈。
- 人形可用主体起伏、侧倾与持物随动；重型角色缓慢转头/重心变化；飞行类绑定翼根；植物让外层枝叶跟随主体。法术和武器不默认套用人物呼吸。
- 背景填补隐藏区域，前景与主角遮挡关系保持合理。所有图层共享画布坐标和尺度，裁切一致。翼根、颈部、手部须在动作两端仍连续。
- 动态与静态不必像素一致，但脸、体型、装备、主色与姿态应能直接认成同一角色。保留手牌静态原图是当前选择，不是待修复的“旧资产”。
- 不承诺未制作的眨眼、表情、布料变形或完整骨骼。位移/旋转图层不能替代这些素材和绑定。

可用的图像请求结构：本角色原图为身份参考；说明每个图层内容；要求同尺寸、同坐标和实际透明 alpha；列出不得改变的面部/服装特征；明确补齐遮挡区域。保留实际请求全文和原始输出。具体例子可读仓库 `assets/motion/PROMPTS.md`，但不要机械复制历史失败素材的剪裁值。

检查 alpha 本身，而不是肉眼看到棋盘就认为透明。若工具输出了画出来的棋盘，用对齐的技术遮罩或重新出图解决。对白毛、肤色、嘴腔、牙齿、火焰逐处检查：遮罩可能把角色内部误认成孔洞，键色阈值也可能让皮肤半透明。白毛、雪和眼睛高光不能当背景一起抹掉。原图像素不能用“全删近白色”这类规则粗暴抠空。若改用纯色底，选与角色本体差异大的键色，固定实际处理参数；过窄阈值可能留下绿边，过宽阈值可能抠穿肤色。背景还应移除属于角色的附肢，不把残留大蛛腿或翼片当环境保留。

## 两个尺度验收

1. **场上真实尺寸**：观察至少一个完整循环，动作应能辨认；不能只有扫光，也不能所有角色同步摇摆。人物应与自己的运动类型相符。
2. **放大尺度**：检查头身连接、翼根、手持物、白边、透明孔洞、错位和露底。观察循环两端与中间位置，不能只检查单张截图。
3. **交互**：手牌 hover/click 不切姿态；同卡多个实例各自冻结/解冻；出牌、变形、死亡与视口旋转没有旧角色残留或空白画布。
4. **资源**：动态层命名/数量与模板一致；whole-subject 不添加空 accent。检查静态栏没有动画请求、满场活跃上限有效、缓存可淘汰；实际测试工具在仓库，不另造一份 skill 专用渲染器。

不合格时修复具体素材、支点或动作。对无法在当前素材上可靠实现的关节动作，选择完整主体模板通常比继续旋转错误的贴片更合适。动画幅度要通过游戏尺寸观察确定，不能靠把参数调大宣称“已可见”。
