# 专用 UI 资产与细节复审 · 2026-09-09

本轮按用户授权，由三个子代理分别制作美术、修复英雄选择、独立审查 UI；主代理负责接入、交叉复查、拒收返工和完整回归。以专业卡牌游戏的材质、信息层级、交互状态和小屏可用性作为标准。使用原创资产，没有复制《炉石传说》的图案。

## 原创美术及返工

| 资产 | 用途 | 接入与评审 |
|---|---|---|
| `hero-laurel.webp` 750×250 | 英雄选项上沿月桂/星火冠饰 | 桌面显示；未选中减弱饱和度；触屏隐藏大冠饰以保留肖像。四位英雄均不遮眼睛与勾选徽记 |
| `collection-spine.webp` 106×1464 | 收藏卡页与牌表之间的五段皮革书脊 | 第一版短书脊被拒收：缩小后像悬空把手。重新生成约14:1细长结构，最终40px宽、约550px高；修正父布局旧flex与新grid冲突，整条处于栏间，不被牌表裁切 |
| `covenant-ring.webp` 384×384 | 契约标题祭坛环与卡片角落印记 | 四石轮廓、空心环与实时职业符号分层；标题和卡片各自适配尺寸，未压文字与进度 |

所有原图、完整提示、裁切参数、尺寸和 SHA-256 在 `assets/ui/manifest.json`、`assets/ui/source-prompts-20260909.json` 与 `assets/ui/PROMPTS.md`。被拒收书脊源图保留。源图真实 alpha，运行 WebP 保留透明通道。仅生产处理裁切/缩放/压缩，不拉扁旧图伪造细长结构。

构建仍通过 `tools/ui_assets.py` 验证源与运行文件并嵌入。卡名、规则、费用、攻血、仪式进度均保持实时 DOM。

## 发现并修复的实际问题

| 问题 | 修复 | 验证方式 |
|---|---|---|
| 英雄右上勾被拱形裁切 | 勾移入真实弧线内部，选中态保留独立高亮与可访问状态 | 每位英雄对勾轮廓8点实际 hit-test；不只检查矩形尺寸 |
| 英雄选择重建界面后焦点/滚动丢失 | 保持原按钮键盘焦点和滚动位置，旧弹窗异步回调不能抢新面板焦点 | 四位英雄逐一 Enter 选择，验证 aria-pressed、焦点和后排滚动 |
| 关闭钮挤压标题、靠边框太近 | 44 CSS px 独立关闭区、标题预留空间 | 手机44屏幕px，桌面缩放后至少32屏幕px；中心实际命中 |
| 手机地图逐字竖排、图文溢出 | 清除退役182px宽度、绝对定位图片、旧手机大左内边距；共享图文网格 | 1600、390、844、568四档标题/正文边界与真实出发按钮 |
| 小横屏手牌详情和失败页按钮在屏幕外 | 两者进入固定底部操作+独立正文滚动，失败页横向紧凑排版 | 568×320按屏幕坐标点击选择目标，实际冻结敌方、扣费；失败返回营地 |
| 回合提示/试玩toast穿透弹窗 | 按整个body的弹窗状态隐藏瞬时战斗提示，兼容移动端重挂载容器 | 真手牌弹窗与契约弹窗检查，装饰提示不覆盖内容 |
| 568横屏展开配置正文仅约10px | 配置独占中间区；正文独立定位滚动，绕开原生details包装层；横屏用页签作标题节约高度 | 出现11项职业不符问题后正文仍≥80px；英雄、契约实际可滚动操作 |
| 大量错误文案挤掉配置/列表 | 简洁错误数量摘要，可展开完整详情；保存禁用规则保持不变 | 收起/再展开、错误状态、底部操作可见与牌表恢复 |

主代理曾发现书脊被侧栏部分遮住，即使子代理已通过审图仍再次修正布局。最终1600视口书脊右界1136，侧栏左界1138；1280缩放视口分别908.8和910.4，二者不相交。
