# 音画反馈优化 · 2026-09-08

本轮在现有 Canvas/DOM 游戏中改进动作因果、卡牌材质、混音和反馈可读性。参考炉石式的起手、接触、短暂停顿、回位和结果层次；不是对商业游戏完整美术、音乐、配音或设备表现达到同等水准的认证。

## 玩家可感知的变化

- 随从从手牌飞向落点，接触桌面时播放纸牌与木质落地音；召唤派生物保留召唤落地声。抽牌使用有金属包边的实体卡背轨迹与独立落手反馈。
- 近战先后撤蓄力，再加速接触；接触点、血量更新、伤害数字与声音由同一个事件拍控制。重击停顿更明显，攻击者回位后由死亡事件统一处理死亡。飞行中的角色血量也实时更新。
- 攻击与反击数字分布在接触区域两侧，手机数字恢复合理尺寸，避免旧的 `!important` 字体规则覆盖手机样式。
- 每组范围伤害只播放一个按最高伤害加权的主撞击音，各目标保留视觉反馈。护甲完全吸收、圣盾破裂与生命损失具有不同声音。
- 补全取牌、拖牌、抽牌、死亡、冻结、增益、武器损坏及操作拒绝的声音；自己/敌方回合与胜/负/平局可从声音区分。回合声音跟随提示出现，不再等整个事件队列结束后响起。
- 设置新增总音量、战斗与操作、酒馆氛围三个滑块，仍写入 `emberfall.settings.v1`。从旧的静音设置恢复、键盘首次操作和再次开声均可解锁音频。

## 反馈节奏与边界

| 场景 | 基础时序 / 行为 |
|---|---|
| 近战 | 起手至接触 220 ms；前 40% 后撤，随后加速；普通/重击接触保持约 22/48 ms；回位在接触后 250 ms 内完成 |
| 法术 / 英雄技能 | 后续特效迭代改为具名法术 320–800 ms / 技能 420 ms；弹道在本拍结束抵达，随本拍缩放，见 [特效记录](VFX_FEEDBACK.md) |
| 手牌随从 | 普通牌 300 ms、传说牌 620 ms 飞向召唤位置，落地后 280 ms 轻微回弹 |
| 命中 → 死亡 → 亡语 | 命中至少保留独立结果帧；正常命中拍 300 ms、死亡拍 400 ms，再开始后续触发 |
| 连续抽牌 | 每张独立 240 ms 拍；卡背飞行 200 ms，再显露实际手牌 |
| 长事件链 | 原有 6.5 秒预算保留；近战接触与回位都随缩放调整 |
| 震动 | 桌面最多 4 px、手机最多 2 px；100 ms 内不重复叠加震动 |
| 减弱动态 | 沿用立即呈现结果的方式；不飞牌、不震动，保留数字和状态提示 |

规则层、AI 决策和事件结果不依赖这些时钟；未修改卡牌或战役平衡。保留 v1 存档及四个存储键。界面仍为 Canvas 酒馆与实时 DOM 卡牌，没有增加 Three.js 或视频播放路径。

## 音频素材与混音

12 段 Kenney CC0 素材共 **108,775 字节 / 5.977 秒**，包含纸牌双落桌变体、挥击、轻重撞击、木质撞击、碎屑、玻璃、钟声及金属卡扣。使用官方 [Casino Audio](https://kenney.nl/assets/casino-audio)、[Impact Sounds](https://kenney.nl/assets/impact-sounds)、[RPG Audio](https://kenney.nl/assets/rpg-audio)。原件、逐文件 SHA-256、许可和处理记录均在 [assets/audio](../assets/audio/CREDITS.md)。没有使用炉石录音。

素材经解码、裁去静音、首尾淡化和峰值处理后编码为 44.1 kHz 单声道 MP3。成品峰值为 −5.48 至 −4.95 dBFS，两段纸牌落桌的强瞬态在约 3 ms 处开始。元素法术仍使用即时合成，与 Foley 材质层混合。ElevenLabs 凭据探测结果为 `ELEVENLABS_API_KEY=MISSING`，本轮没有声称使用 AI 生成录音。

运行时：

- 首次用户手势才创建 AudioContext；异步解码不延迟游戏动作，缺失或未解码时使用即时合成。
- 音效、操作、环境三条总线；场内位置映射到有限的左右声像；重复非旋律声音在 ±3% 音高范围变化。
- 共享 0.48 秒短混响，36 Hz 高通，输出压缩器；战斗声音压低环境底声，避免掩盖接触声。
- 最多 20 个声音实例；连续重复提示节流，优先保留重要声音；每个实例管理自己的音源、节点与结束清理。
- 取消演出、返回、静音、页面隐藏会停止活动音源；页面恢复后不会补播已过去的音效。旋转与抽牌取消也会恢复手牌可见性。
- 便携单文件内嵌同一份音频；网页构建提取成内容哈希命名的本地 MP3，游戏运行不请求第三方音频网站。

`python3 build.py` 调用 `tools/audio_assets.py` 校验素材哈希并生成 `src/audio-assets.js`，无需新增 Python 或 npm 依赖。源录音的再次加工才需要 FFmpeg；常规构建不使用它。

## 验收

使用项目原有 Playwright 框架，扩展 `tests/e2e/audio-feedback.spec.cjs` 和 `tests/audio-assets.test.cjs`。验收覆盖用户手势解锁、旧静音设置恢复、滑块持久化、12 个样本解码、桌面/触控命中同步、AOE 合并声音、护甲音色、声音实例清理、胜负提示、单文件内嵌音频，以及抽牌旋转清理。

- 首轮完整 `npm run test:release`：83 项规则/素材测试、4 项美术测试、68 项浏览器测试全部通过。
- 最终 `npm run test:release`：83 项规则/素材测试、4 项美术测试、69 项浏览器测试，合计 **156 项通过**，无失败、无跳过、无重试通过项。完整浏览器阶段约 175 秒。
- 混音测量通过真实 Chromium Web Audio 输出处的 AnalyserNode：10 种提示同时触发，最终回归测得峰值 **0.4862**（约 −6.26 dBFS），73 个采样帧，最多 10 个活动声音，取消后活动声音为 0；音频运行错误为 0。该值针对这次压力场景，并不是全部声音组合的峰值保证。
- 接触测试在桌面与 390×844 触控模拟中同时检查伤害数字、声音时刻和攻击动画接触时刻；允许音画观察差小于 70 ms、动画接触误差小于 80 ms，避免把截图捕获调度误差误判为音频延迟。
- 视觉检查实际查看了桌面/手机命中与手机音量设置截图；修复数字尺寸及反击遮挡后再次检查。既有完整回归还覆盖手机横竖屏、存档恢复、手牌、传说入场、冻结和亡语。

截图由测试生成在 `artifacts/qa/feedback-contact-desktop.png`、`feedback-contact-touch.png`、`feedback-settings-touch.png`。JSON 测试结果位于 `artifacts/qa/results.json`；不把这些生成文件提交为源码。

没有实体手机、Safari、蓝牙设备输出延迟或受控主观听感对比结论。自动验证证明事件同步、播放与清理可用，不代表已经达到炉石完整音频制作水准。本次仅更新本地源码与构建，未发布公开站点。
