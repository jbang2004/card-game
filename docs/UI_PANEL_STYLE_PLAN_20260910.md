# 面板视觉统一重构方案

## 范围与依据

根据当前源码的19种注册弹窗、各入口的实际内容结构及新版地图视觉制定方案。用户随后批准实施，并要求清理冗余后提交部署；以下方案作为本次重构的设计依据。

基准是新版地图的深胡桃木、薄古金边框、小角饰、暖白宋体标题、清晰的内容与操作分区。地图的地形、路线、拱形地点是专属内容，不应复制到全部界面。

## 共同设计系统

- 提取地图私有的木纹、古金、暖白、次级墨色、纸色为公共令牌；材质及配色位于 components 层，布局位于 dialog-layout。
- 统一面板外框、四角、标题区、44px关闭按钮、主次按钮、输入框、下拉框、选中态、禁用态和滚动暗示。
- 深木外壳承托内容；羊皮纸用于长文和铭牌；深色衬底用于卡牌和原画展示。降低图片背后的纹理对比。
- 标题建议24–30px，正文14–16px，辅助说明12–13px；宋体只用于标题和名称，规则说明使用清晰黑体。
- 金色主按钮只对应当前主要动作；选中、可用、已完成必须有文字或符号，不单靠颜色。
- 只对需要独立变化的对象分层：人物原画、卡框、徽记、数值、规则、进度各自保持独立。
- 不给所有弹窗同一个高度。内容决定自然高度，视口限制最大高度；溢出时保留纵向滚动与可达操作。
- 普通面板一个滚动区；收藏的卡库与牌组允许各自滚动。标题与操作区不参与内容滚动。
- 用容器宽度决定布局，不以是否触控决定主题；旋转不丢选择、草稿或战役状态。
- 当前地图的少量小号标签也应随公共字号规则改善，不能把基准已有的弱点复制出去。

## 逐面板方案

| 面板 | 重构方向 | 桌面 / 手机 |
| --- | --- | --- |
| 英雄选择 heroes | 四位英雄同等尺寸的独立竖幅画像；下接名称铭牌和唯一一次能力说明。准备区整合套牌、曲线、契约、打法；删除“同一页完成”等解释界面自身的文案。 | 宽屏四列，下方分区准备；中屏2×2；窄屏按可读性改双列或纵向，不强塞四列。 |
| 收藏 library | 木框收藏册，标题与搜索统一；筛选紧凑排列；卡片仍使用完整标准卡面，不套地图拱框。卡名、规则、攻血不随断点消失。 | 桌面卡库+牌组；手机卡库/牌组视图切换，各自纵向滚动，切换不清草稿。 |
| 收藏内牌组编辑 | 英雄身份、牌组名、30/30为一个紧凑头部；条目对齐费用、名称、张数。配置可折叠，错误贴近相关操作。 | 桌面约280–340px有界侧栏；手机独立视图，保存按钮固定可达。 |
| 诸神契约 contracts | 继续使用有上限的竖面板；神图保持固定比例，名称和状态叠加在图下部，长规则进入自然高度正文。统一金框和木纹，保留仪式颜色。 | 友方、敌方分段纵向展示；多契约滚动。禁止不同神祇的多个按钮脱离对象堆在底部，采用选中契约+对应动作或卡内动作。 |
| 起手 mulligan | 深木牌桌、完整等比卡面；替换状态用印章和边缘强调。说明一处，操作随内容落位。 | 宽屏三/四张并排；窄屏网格或纵向，不压扁、不藏规则、不撑出空白。 |
| 发现 discover | 与起手共用卡牌选择容器。保留现有点击即选择的规则，视觉提示明确，不擅自加入确认步骤。 | 根据最小可读卡宽换列，纵向滚动。 |
| 遗物 rewards | 遗物原图置于独立小展台或绒面托底，名称铭牌+效果说明；选中高亮。下方保留可选整备与下一站。 | 宽屏并列，手机纵向；底部明确已选遗物与继续按钮。 |
| 战役整备（奖励内） | 作为同一面板次级区域；移除与补充卡牌用两个对齐字段，错误紧邻字段。 | 宽屏双列，手机纵排，展开不挤压遗物卡。 |
| 结果 result | 单一胜负徽记与标题，少量金色强调；三项统计作为一条摘要，不堆大统计卡。胜利、失败、通关用同一骨架不同徽记。 | 内容自然高度，主要按钮明确，矮屏允许滚动。 |
| 设置 settings | 木框控制页，以分隔线区分声音、画面、操作；统一开关、滑杆和百分比对齐。 | 保持单列可读，长内容滚动；重试等操作与普通设置分隔。 |
| 手册 help | 木框中的低对比羊皮纸正文，目录锚点、章节编号、关键词说明；清除高层统一隐藏说明的处理。 | 桌面可设窄目录栏；手机折叠目录，正文单列滚动，限制阅读行宽。 |
| 战斗卡牌详情 inspect / touch-card | 共享标准卡面与详情结构，实际增益、关键词和可执行动作有明确层级。移除内联固定650px和旧棕色说明文字。 | 宽屏卡面+旁注；手机卡面+下方详情。不可因窄屏重复两遍相同规则。 |
| 收藏单卡 library-card | 与战斗详情共享展示组件，但保留加入牌组、数量限制和返回收藏语义。 | 竖幅详情优先，宽屏适量分栏；不无边界放大原画。 |
| 英雄/首领详情 touch-hero | 统一头像、生命/护甲、技能、武器/阶段信息。敌方阶段与玩家可用动作分别标识。 | 宽屏图文分栏，手机纵向，44px以上操作。 |
| 手牌总览 touch-hand | 木框手牌托盘，统一等比完整卡面；费用/不可用原因就近说明。 | 自适应网格，始终纵向浏览；点击进入已有详情流程。 |
| 菜单 touch-menu | 紧凑木框导航，统一图标、行高、金色焦点，减少无关操作教学文案。 | 根据宽度一/两列，内容决定高度。 |
| 战斗记录 touch-log | 日志册式单列时间顺序；回合号为页边标签，我方/敌方用小标记与文字区分。 | 单一纵向滚动，保留当前日志行为，不把每条记录包装成大卡。 |
| 原画档案 atelier | 深木画廊，原画完整比例与细金框，图片下方简短图注；卡牌样本作为次级区。 | 宽屏网格，手机单列，尽量完整展示原画而非全铺裁切。 |
| 确认 confirm | 同材质的轻量短对话框，动作名称具体，正文直述后果。 | 建议最大宽420–480px，自然高度；取消和确认清晰可达。 |
| 地图 map | 提取公共样式后保留地形、节点与路线专属部分。统一辅助字号，检查加载、选中、锁定、已完成状态。 | 三列/两列/纵向结构继续保留。 |

## 实施顺序

1. 公共材质、标题/关闭按钮、主次控件、尺寸与滚动约定。将地图也接入公共组件，避免地图变成第二套主题。
2. 英雄、收藏/牌组、契约：优先覆盖高频且内容最复杂的流程。
3. 起手、发现、奖励/整备、结果：贯穿一局的连续视觉。
4. 详情、手牌、设置、手册、菜单、日志、原画与确认：补齐全部面板。
5. 在每个面板迁移完成后，删除其失效旧覆盖和内联样式，避免继续追加 !important 补丁。

## 源码发现与边界

- 地图材质当前为 --map-* 私有令牌；应该提升为通用材质体系，而不是将所有选择器都冠以 atlas。
- dialog-layout.js 已有19种类型与统一滚动生命周期，应复用，不另建第二套弹窗管理器。
- dialog-layout.css 中存在统一隐藏标题段落的规则；迁移时要按语义决定说明是否展示。
- enhancements.js 的 inspect 仍含固定宽度、flex和旧颜色的内联样式，需和 library-card、touch-card共同整理。
- contracts.js 的每个友方契约按钮都标为 data-dialog-action，mount 会把它们移入统一底部。多契约时对象与动作的关系必须重新设计。
- 英雄选择与手册源码仍含练习对战入口/描述。此前“删除演武场”的范围如涵盖该玩法，应另行核对残留；本轮没有静默删除玩法。
- 战斗 HUD 和酒馆首页可在最后同步字体与按钮，但不套弹窗大木框，不遮挡战场。

实施阶段仍需保持现有用户选择、存档规则、组牌校验、卡片比例和手机滑动行为。样式统一不等于把所有面板做成相同大小、相同背景或相同排列。

## 实施记录

- `presentation/components.css` 统一木纹、颜色、边框与控件；`presentation/dialog-layout.css` 统一尺寸、卡面比例与容器断点，清理多轮叠加的弹窗覆盖。
- `presentation/dialog-layout.js` 是唯一弹窗布局生命周期：标题关联、收藏页签、纵向滚动提示及观察器清理。删除手机重复挂载、短屏输入框搬移、重复筛选下拉与按钮集中搬移。
- 契约动作保留在所属卡片内，底部只提供关闭；长规则自然增长，滚动后仍可操作。
- 战斗、手机和收藏详情使用统一的 `card-detail-layout/art/copy` 结构，保留完整卡面和各场景动作。
- 移除英雄选择中解释界面本身的文案、重复人物描述；保留英雄技能、套牌规则与当前玩法。
- 旧整张地图图像已删除，可从 Git 历史恢复；独立地形、木纹、地点素材与 DOM 路线继续使用。
- 未移除仍在使用的规则、当前存储格式校验、触控手势抑制和 HUD 样式；这些不是废弃兼容代码。
- 收藏侧栏的身份、配置、条目与曲线归入同一个滚动区，保存操作独立；避免矮屏中多个嵌套滚动区互相争抢高度。
- 本次构建、JS/CSS解析及116项规则/素材检查通过；浏览器抽查覆盖1440、881、390宽度与568×320横屏，未进行实体手机或全量浏览器套件验收。
