# 界面与交互独立审计 · 2026-09-13

本轮以实际操作、阅读和维护成本为依据，不以参考图相似度为验收条件。保留既有银蓝材质与卡牌插画，调整有证据支持的问题；不改对局规则和存档格式。

## 结论与已修复项

| 问题 | 对使用者的影响 | 最终处理 |
| --- | --- | --- |
| 收藏页四个“页签”并非四个页面：图鉴只聚焦搜索，构筑只展开编辑器，演练重复底部操作 | 选中状态与内容不一致，重复入口分散注意力 | 删除整组模拟导航及其事件、样式和高光注册；保留唯一标题/搜索、类型/费用筛选、真实牌组编辑及开战入口 |
| 收藏页搜索与筛选依赖固定绝对坐标和预留空洞 | 中等桌面尺寸间距不均，内容关系不清楚 | 标题和搜索回到同一流式标题行；筛选独立成行，可换行；桌面左右两栏和手机卡牌/牌组入口保留 |
| 设置总音量位于“操作”，目录只滚动而内容仍堆在一起 | 分类不准确，设置位置难预测 | 声音含总音量/音效/氛围与声音开关；画面含动态、画质、时光、全屏；操作含行动加速与手势说明；一次显示一个分类 |
| 设置为参考构图固定偏右，面板面积过大 | 操作区与视觉中心不一致，留白失衡 | 桌面居中，最大 1100 px 宽、660 px 高并受视口约束；手机继续独立布局和单纵向滚动 |
| 手册与设置各自维护分类选中、隐藏等状态 | 相似交互实现不一致，缺少统一键盘行为 | 抽象 `EmberDialogs.tabs`，统一 panel 可见性、ARIA 关联、单一 Tab 入口、方向键/Home/End、随尺寸更新方向；关闭对话框清理观察器 |
| 手册将出牌与攻击表达为强制固定阶段 | 误导新玩家的战术选择 | 三步模型：回合开始 → 自由行动 → 结束回合；明确出牌、攻击、技能可穿插 |
| 手册“让冒险开始”实际只关闭手册；查看说明仍指定已不存在的左侧大图 | 按钮承诺与行为不符 | 改为“返回游戏”，查看说明与现有中央详情层一致 |
| 竖屏手册四章仅露出前两章，依赖无提示的横滑 | 后两章可发现性差 | 竖屏两列四入口，全部直接可见 |
| 设置改为分类后，旧矮横屏网格将新增声音开关挤出边界 | 568×320 下控件越界 | 分类面板显式使用单列块布局，内部滑杆仍使用紧凑布局 |
| 模态焦点循环枚举了 tabindex=-1 按钮与禁用输入 | 与分类的单一键盘入口语义冲突 | 焦点循环排除负 tabindex 和 disabled；新增实际键盘回归 |

| 简短确认框被固定为 940×500，按钮大于任务需要 | 视觉权重与简单决策不匹配 | 桌面收敛到 640 px 宽、内容自适应高度，说明左对齐，操作区紧凑；手机尺寸与命中区域保留 |

## 经核验保留的设计

- 点牌 → 点战场/目标确认是当前防误触行为，不属于冗余步骤。拖动仍可一次完成出牌。核对 `selectCard` / `prepareCard` 后保留逻辑，并修正 README 中过时的“无目标牌直接打出”描述。
- 手机卡牌与牌组分视图解决有限宽度问题；桌面并列编辑更适合比较，因此不强行统一为同一布局。
- 契约进度、起手替换状态、奖励确认与失败重试各有实际决策意义，保留；未仅因“简洁”删除玩法信息。
- 战斗中的伤害/法力/目标反馈有对应状态来源；表现层与规则层继续分离。首页、地图、英雄、起手、战斗、契约、奖励、结算与二级对话框通过真实路径截图和回归复查。
- 既有 CSS 的历史文件名不等于无效代码。只移除明确被退役导航遗留的规则，不盲删仍参与排版的基础层，也不新增 UI 框架。
