# 内容与卡组模型改进

## 边界

保留现有纯规则引擎、同步结算、Canvas 表现和全部内容 ID。英雄用 `id` 表示身份、`classId` 表示职业；卡牌的 `class` 继续引用职业 ID。职业与种族来自内容注册表。英雄通过 `defaultDeckId` 引用职业预设，加载后派生只读 `deck`，不重复维护两份牌表。预设的 `hero` 是练习对手的英雄身份，`classId` 决定构筑；同职业英雄可共用预设。

`deckRules` 是牌数、同名上限及稀有度例外的唯一配置；内容加载、开局、卡组编辑和战役整备共用纯校验器。英雄/首领/遗物/预设分别校验字段、ID 唯一性、数值和跨表引用。首领仍按原数组顺序推进，使用当前 bossIndex 标识关卡；结束位置从内容长度推导，追加关卡无需修改界面。已有首领的删除、重排仍需存档迁移，不属于本次兼容操作。

## 测试期格式决策（2026-09-08 用户最新要求）

用户确认没有需要保留的旧对局，取消前一轮的向后兼容要求。战役只接受 `{version:2,...}`；不读取旧 version 1、旧 ruleset、legacyDeck 或缺失 modifiers 的状态。触发与发现始终执行当前规则，临时攻击只由 modifiers 记录和到期结算。

卡组只接受 `{version:2,activeId,decks:[{id,name,heroId,cards}]}`，不适配旧数组。旧格式/损坏内容不自动转换；收藏可明确重建为空集合，再保存新牌组。四个既有存储键沿用，键名与支持格式独立。设置与世界偏好不受对局格式清理影响。

## 验证

覆盖当前对局跨刷新恢复、旧格式拒绝且不改变运行对局、所有 62 张卡的确定性结算与可恢复状态、增益保存后到期、职业限制不可绕过、命名卡组读写与重建、写入失败、同职业多英雄、新职业及追加第六关。完整运行构建、规则/素材测试与 Playwright。
