# 英雄选择 / heroes

## 目标与当前状态

当前参数区接入 [共享 SVG 四角面板](../SHARED_PANELS.md)，统一四边内边距与分节间距；全屏原画不套外框。短横屏名单随同一内容区滚动，避免固定名单高度超过可视区。

2026-09-13，按 concepts 中对应参考接入既有可玩游戏。当前已实装，未发布；用户尚未确认视觉验收。卡牌插画继续使用当前严格 ID 映射；卡名、规则、数量和状态取真实游戏数据。

## 元素拆分与当前实现

- 实现入口：`src/application/screens/heroes.js`；统一材质由 `src/presentation/components.css` 消费，场景由 `EmberTheme` 的语义角色解析。
- 范围：英雄名单、技能、费用曲线、战役/练习模式、契约选择、进入战斗。
- 位图只承担场景、复杂材质、遗物和徽记；文字、数值、规则、选择状态与按钮保留实时 DOM；简单图案由 `EmberArt` 原生 SVG 提供。
- 新生成素材的提示词、源文件、格式、SHA-256 和 Alpha 实测见 [provenance.json](../../../assets/ui/page-reference-v1/provenance.json)。生成模型未由工具返回，记录为未核实；WebP 仅作格式封装。生成重建不等于无损分层。

## 页面动作

入口：主页「选择英雄」。所有按钮沿用既有动作接口；测试中的状态夹具用于打开胜负、发现和奖励页面，不进入生产接口。

## 批注与迭代结论

排除了旧 absolute/margin/广泛选择器造成的覆盖；桌面卡牌维持同一图区比例和按规则长度变化的字号。横屏提示移出单位区域，敌方法力移到英雄旁。新增设置导航、模式按钮和契约槽位均绑定实际状态。

已知差异：参考包含与当前内容库不同的卡名、数值、配置与装饰性文案，实装显示当前真实内容；背景和复杂徽记为图像重建，纹理与边界不是原图逐像素复制；部分细边框、字形、按钮轮廓仍由现有主题及 SVG 重建。没有计算排除卡图后像素误差为零，不能将交互测试通过称为像素一致证明。

## 2026-09-13 浏览器批注：视觉纪律

本轮以用户 1132×1074 实装批注为依据，不追随旧参考构图。前次只验证外框与点击区域，漏检了文字/图案内部关系，此处修正验收边界。

1. 契约标题、菱形槽位与数量、配置说明各占独立流式行；取消说明的 `left:40%` 绝对定位。
2. 桌面右栏至少 400 px；底部操作同宽同高、52 px 高，文案收敛为“调整牌组 / 开始冒险（开始练习）”，字号 18 px；窄竖屏 16 px。图标、文字、按钮边缘分别留出空间。
3. 技能标题为真实 DOM，移除原伪元素横线和游离星点；图标在 64 px 圆形容器内居中，说明独占弹性列。
4. 右上品牌距右侧 104 px，关闭按钮保留独立空间；品牌字号减小，避免两者争抢视觉位置。
5. 英雄选项以整行底色与细边缘表示选中。桌面选中勾独占末列，手机竖屏独占头像/名称下方一行，手机横屏独占末列；不叠加于圆形头像。
6. 英雄主景直接绑定该英雄卡牌的 `portraitId` 正式高清图，不再使用同主题的近似人物图；四张英雄卡以 768×1024 打包。技能符号按英雄能力绑定：星火、黎明旗帜、游侠长弓、送魂灯笼，英雄选择页与战场技能按钮共用同一数据字段。

保留既有位图材质，本轮无需新纹理；修正属于排版、原生图标定位与选择状态构成。新增 `visual-discipline.spec.cjs` 及几何检查 helper，覆盖 1132×1074、1100×650、1280×720、1672×941 与手机横竖屏。详见 [本轮截图与验证](../../../output/visual-discipline-20260913/VALIDATION.md)。

## 2026-09-13 跨尺寸材质统一

英雄参数区复用诸神数值面板的深色玻璃、银蓝细框与四角装饰；标题、技能徽记、套牌选择器、契约分隔及其字体语义在桌面、竖屏和短横屏共用一份组件规则。断点只调整栏位、尺寸、间距和字号，不再切换字族、颜色、边框、背景或选中反馈。`responsive-component-style.spec.cjs` 通过真实英雄切换流程比较三种视口的计算样式，并覆盖选中英雄、技能、牌组、玩法和契约状态；用户批注对应的 1459×996 也已加入页面几何回归。

## 2026-09-14 触控布局皮肤

`?skin=slate` 第二阶段：`heroes.css` 拆成两段。材质与字体（缩略图 8 圆角 + 1.5px 卡描边、列表行发丝线、「选择英雄」药丸、预览卡描边与投影、模式卡选中蓝边发光）改用 `html[data-skin="slate"] body` 前缀，桌面与触控共用一份；桌面几何（`[轨 200][清单 400][预览 1fr]` 三栏、预览卡绝对定位）仍在 `body:not(.touch-layout)` 下。

触控几何：竖屏 390×844 单列——紧凑英雄行（56px 缩略图 · 名称 · 技能一行 · 96px 小药丸，行高 76px），导航轨节点整体隐藏，配置分节顺次排在名册之下；模式卡与套牌下拉均为整宽 44px 以上。横屏 ≤500px 高与平板 1024×768 改为两栏：预览卡独占左列（横屏 132×178、平板 240×344），名册与配置共用右侧单一滚动列，平板下名册与配置再分两栏。

偏差：简报要求「名册 → 预览卡 → 配置」的竖屏顺序。`screens/heroes.js` 把 `.scene-showcase` 写成 `.folio-pane` 的兄弟节点，不改 DOM 就无法把它插到名册与配置之间，因此竖屏把它从 `inset: 0` 满屏底图改成标题行下方居中的 200×270 卡片。这样既消除了基线缺陷（配置文字直接压在原画上），也不必给 `.hero-configuration` 添加桌面没有的背景。

验收：390×844 / 844×390 / 568×320 / 1024×768 截图见 [output/slate-mobile-pages-20260914](../../../output/slate-mobile-pages-20260914/)。桌面 1672×941 与 `output/slate-skin-test-20260913/heroes-slate-1672x941.png` 像素差为 0。
