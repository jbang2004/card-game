# 招式单：角色动作与特效的调校

2026-10-02 用户确定的工作方式：用户逐个角色看效果、口述意见，由 Claude 调整。本文件是这套流程的约定，改格式先改本文件。角色造型、站位、打击感分档仍见 [MINIATURES.md](MINIATURES.md)。

## 1. 三样东西

| 东西 | 位置 | 作用 |
|---|---|---|
| 招式单 | `src/content/moves.js`（`EmberMoveSheets`） | 每个战场角色的动作节奏与特效，纯数据。**调动作和特效只改这里。** |
| 编译器 | `src/presentation/voxel/movesheet.js`（`EmberMoveSheet`） | 把招式单编译成运行时读的表（`EmberModelFigures` 的动作套件、`EmberSkillFx` 的特效配方），并负责校验、时间轴、中文名 |
| 审片台 | `tools/move-review/` | 给用户看的页面、给 Claude 用的自检命令 |

运行时代码（`models.js`、`arena.js`、`skillfx.js`）不再保存任何角色的数值；它们读编译结果。

## 2. 招式单的写法

单位：时间是毫秒，大小是角色身高的倍数，帧号是动捕片段的帧（30 帧/秒）。

```js
paladin: {
  base: "melee",                         // 原型（也可以是另一个角色）
  name: "圣光裁决者", move: "圣光裁决", note: "蓄力 → 旋身跃起 → …",
  clips: { idle: "st_axe", attack: "ss_power", hurt: "ss_impact", victory: "vc_raise_hand" },
  attack: {
    before: {                            // 命中前，按顺序；各段 ms 之和就是「到命中的总时长」
      coil:   { ms: 132, frame: 11,   ease: "io" },   // 这一段多长 · 结束在片段第几帧 · 进入方式
      hold:   { ms: 48,  frame: 12.5, ease: "o" },
      spring: { ms: 300, frame: 28,   ease: "o" },
      strike: { ms: 120, frame: 33,   ease: "i3" },
    },
    after: {                             // 命中后
      follow: { ms: 100, frame: 37, ease: "o" },
      settle: { ms: 260, frame: 41, ease: "io" },
      rise:   { ms: 340 },               // 起身回到待机姿势
      home:   { ms: 320 },               // 跳回原位
    },
    dash: { kind: "leap", ms: 420, reach: 0.42 },     // 命中前多久离开站位 · 落点离对手多远
    hitstop: [3, 5, 7],                               // 轻 / 中 / 重击的定帧（帧）
  },
  fx: {
    palette: "holy",
    charge: { sigil: "sun" },
    hit: { ground: "crack", bits: "feather" },
    hurt: { at: "shield" },
    idle: { bits: "sparkle" },
  },
}
```

- **缓动**：`io` 慢起慢停 · `o` 快起慢停 · `o3` 更快起 · `i3` 慢起快停（出手）· `l` 匀速。
- **`kind`**：`melee`（近战，冲到对手面前）· `caster`（施法，原地）· `archer`（弓手）· `beast`（兽类）。导演层自己的节拍算在总时长里：近战是抬起 110 + 冲出 150，远程是后坐 90。所以近战的总时长不能短于 260 ms、远程不能短于 90 ms，多出来的部分就是这个角色自己的蓄力，由编译器推出，不再单独填写。
- **兽类**没有动捕片段（动作是各自文件里的代码），招式单只管节拍与特效：`attack: { windup, dash: { kind, at }, hold, after: { rise, home }, hitstop }`。`at` 是离开站位的时刻占总时长的比例；远程兽类（龙的吐息）用 `draw`（出手前的毫秒数）代替 `windup`。
- **`aim: { 动作: … }`**：武器指向。`up` 朝天 · `target` 指向前方（突刺）· `foe` 挥砍的最后一段落到对手身上（对手比自己矮或高时用）· `raised` 举过头顶时朝天 · `[x, y, z]` 固定方向。
- **`dash.reach`**：出手时离对手多远（× 自己的大小）。人形默认按武器长度；兽类按模型实测，让嘴、角或喙刚好到对手近侧。
- **`stretch: { before, after }`**：把命中前或命中后所有阶段整体拉长或缩短的倍数，适合“这一类都慢一点”。
- **`plain`**：招牌动作替换掉的旧版套件，只给试作页的“原版”开关用，字段沿用运行时的名字。

### 特效按播放时刻分组

| 组 | 何时 | 内容 |
|---|---|---|
| `charge` 蓄力 | 命中前 | `sigil` 脚下法印 · `motes` 聚能光点的形状 · `column` 升腾光柱 · `dim` 舞台压暗 · `lantern` 提灯变亮 · `vanish` 遁影烟 |
| `weapon` 武器 | 出手前后 | `glow` 武器发光 · `limb` 用拳脚当刀光 · `trail` 刀光（`from` 从蓄力的几成开始、`inner` 内缘） |
| `cast` 施法 | 命中前 | `kind` 飞弹 / 天降 / 地涌 / 剑阵 / 火柱 / 坍缩 / 灵矛 · `hand` 施法手 · `blades` · `sky` · `look` · `sigil` |
| `hit` 命中 | 命中时 | `flash` 闪光强度 · `mark` 刀痕 · `beam` 光柱 · `ground` 地面痕迹 · `spikes` 地刺 · `rocks` 碎石 · `bits` 飞散物 · `dust` · `shake` · `flame` · `drain` · `implode` · `lift` |
| `hurt` 受击 | 被打时 | `at` 盾上 / 身上 |
| `victory` 胜利 | 胜利动作 | `ray` 天光 · `orb` 身后天体 · `rain` 飘落物 · `flame` · `shock` |
| `idle` 待机 | 站着时 | `bits` 环身飘浮物 · `every` 间隔 · `halo` 脚下光环 |

另有 `palette`（配色）、`size`（全部特效的大小）、`style: "modern"`（神的打法：速度线与贯穿光痕，不用大光球）。

### 单个元素的微调

任何一个元素都可以写成 `{ kind, size, gain, life, count }`：大小、亮度、持续时间、数量的倍数。不写就是 1，画面与原来逐值相同。

```js
hit: { ground: { kind: "crack", size: 0.5 }, beam: { size: 0.8, gain: 0.6 }, shock: { size: 0.7 }, sparks: { count: 0.5 } }
```

可微调的元素：`charge.sigil`、`charge.stream`（聚能光流）、`charge.column`、`weapon.glint`（刃尖闪光）、`weapon.trail`、`hit.burst`（命中闪光）、`hit.mark`、`hit.shock`（冲击环）、`hit.beam`、`hit.ground`、`hit.spikes`、`hit.rocks`、`hit.sparks`、`hit.bits`、`hit.dust`、`hit.flame`、`hurt.flash`、`victory.ray`、`victory.orb`、`victory.rain`、`idle.bits`、`idle.halo`。其中 `stream`、`glint`、`burst`、`shock`、`sparks`、`hurt.flash` 是一直有的元素，只能微调、不能关。

## 3. 原型

`archetypes` 里是一类角色共有的东西；角色的 `base` 指向原型，自己只写不同之处。改原型的一个数，这一类全部跟着变。

```
melee 近战 ── swordShield 剑盾劈砍 · crossSlash 十字斩 · spear 长枪突刺 · swipe 重臂横扫 · punch 重拳
caster 施法 ── throwCast 掷出法术 · sweepCast 挥扫法术 · lanternCast 提灯施法 · prayerCast 祷告施法
archer 弓手      god 神      beast 兽类
```

- 值写 `null`：去掉原型给的那一项（回到默认）。
- `{ _replace: true, … }`：整组阶段换成自己的（阶段的名字或数量与原型不同时用）。
- 镜中英雄 `base` 指向本尊，招式完全相同。

## 4. 审片流程

```bash
python3 tools/move-review/serve.py        # http://127.0.0.1:8013/ ，不需要构建
```

页面直接读 `src/` 下的代码与招式单。保存 `moves.js` 后约一秒内页面自动重读并重播当前招式。

- **看**：换角色、选动作（攻击 / 重击 / 致命一击 / 受击 / 重创 / 阵亡 / 胜利 / 登场）。视角有对局、正面、侧面、特写、俯视（看两人站位）。时间轴上每一段是招式单里的一个阶段；左下角实时显示当前阶段名、毫秒、片段帧号和正在播放的特效。可暂停（空格）、逐帧（← →）、点时间轴跳到任意时刻、⅒ 速慢放；暂停时可以转镜头看定格的一帧。
- **说**：右侧“招式单”用中文列出这个角色的每个阶段和每个特效，以及它们在招式单里的名字。口述时直接说这些词，例如“蓄力再长 100 毫秒”“地面痕迹小一半”“飞散物换成雪花”。
- **留言**：右侧面板最上面是“你的意见”。每个角色的每个动作（整体、攻击、重击、致命一击、受击、重创、阵亡、胜利、登场、待机）各有一条：点“满意”或“要改”，在文本框里写想法，写完自动保存到 `tools/move-review/notes.json`。勾“附上暂停的这一刻”会把当前毫秒和阶段一并记下。有留言的动作和角色带圆点（红：待处理，蓝：Claude 已处理，绿：满意）；“全部留言”列出所有角色的留言，点一条跳回那个动作。Claude 改完后的回复显示在留言下面；用户再写新内容会重新变成待处理。
- **标记**（M）：暂停在想说的那一刻点“标记这一刻”，角色、动作、阶段、毫秒、帧号和截图存到 `tools/move-review/marks/NNN.json` 与 `.jpg`。之后只需说“看标记 3”。
- **对比**：“对比上一版”把保存前的版本放在左边同步播放。每次保存前的版本都留在 `tools/move-review/revisions/`，“回到上一版”就是把那个文件拷回去。

时钟是页面自己的（虚拟时钟加固定随机种子），同一招每次播放完全相同，所以“跳到第 512 毫秒”是把这一招从头重放到那一刻。

审片台里的导演节拍是 `EmberTiming` 的同一组数，但它不是实战：没有卡牌界面、镜头是试作页的。动作和特效定稿后仍要在真实对局里看一次。

## 5. 自检

```bash
node tools/move-review/audit.cjs paladin spark    # 指定角色
node tools/move-review/audit.cjs --all            # 全部（70 个约 3 分钟）
node tools/move-review/audit.cjs --verbose paladin  # 连通过的项也列出
```

每个角色逐帧播放攻击、重击、受击、重创、胜利、待机六种动作（每种都从重新建好的角色开始，所以单独重放得到同样的结果），输出 `tools/move-review/audits/<id>.jpg`（关键时刻联络图，每格 640 宽：攻击各阶段末、命中、对局视角、俯视、其余动作，以及每个被标出项最糟的那一帧）和 `<id>.json`。

身体用包住骨骼的胶囊近似（半径取该骨骼自己蒙皮里最近的 30%，所以大衣、裙摆、披风不算身体；手持的金属不算身体）。兽类没有胶囊，直接取蒙皮顶点。这是“往哪看”的指引，不是结论。

| 检查（标识） | 含义 | 阈值 |
|---|---|---|
| `attack.near` | 近战：整段攻击里武器尖（拳脚、兽类的身体前端）离对手身体表面最近多少 | ≤ 0.25 身高 |
| `attack.held` | 近战：命中前后两帧内武器离对手多远（定帧时刀应该在对手身上） | ≤ 0.25 身高 |
| `attack.landing` | 近战：出手的手在命中前 130 ms 内的速度，占全程最快时的比例（发力太早就没有打击感） | ≥ 40% |
| `attack.facing` | 命中时身体朝向与对手方向的夹角 | ≤ 35° |
| `attack.white` | 隐藏角色只量特效：命中 150 ms 后对手身上仍过曝成白的比例 | ≤ 27% |
| `attack.extent` | 命中闪光峰值时，光离对手中心最远多少 | ≤ 2.9 身高 |
| `<动作>.pop` | 相邻两帧任一骨骼的最大转动（手指、头发披风的弹簧不算；命中那一帧不算） | ≤ 120° |
| `<动作>.jump` | 相邻两帧角色的位移 | ≤ 0.45 身高 |
| `<动作>.sink` / `.under` | 脚比站立时低多少 / 手、头、膝、胯到地面以下多少 | ≤ 6% / 3.5% 身高 |
| `<动作>.tipUnder` | 武器到地面以下多少 | ≤ 8% 身高 |
| `<动作>.weapon` | 武器穿入自己身体某一段的深度（1 = 到骨骼中心；腿部放宽，弓不查） | ≤ 82% |
| `<动作>.hand` | 手进入自己躯干的深度 | ≤ 80% |
| `<动作>.bodies` | 与对手躯干的重叠 | ≤ 55% |
| `<动作>.through` | 兽类：身体最前端越过对手近侧多少 | ≤ 0.22 身高 |
| `victory.ray` | 胜利的天光落在武器尖上：武器尖应举过头顶 | — |

阈值在 `app.js` 的 `LIMIT`。看过并确认没问题的项写进 `tools/move-review/accepted.json`（`{ 角色: { 检查标识: 原因 } }`），之后报告为“已确认”而不是“要看”；用户说“这个可以”时也记在这里。命令只在招式单本身有错时返回非零。

`Review.film(act, from, to, { n, view })`（页面里）把一段动作的连续 n 帧存成一张图，用来看某个数值指向的那一瞬间。

单元测试 `tests/moves.test.cjs` 检查招式单的格式、片段与配色是否存在、与导演节拍是否自洽，以及编译结果。

## 6. 调校时的规矩

留言的处理（Claude）：

```bash
python3 tools/move-review/notes.py                     # 待处理的留言
python3 tools/move-review/notes.py --all               # 全部
python3 tools/move-review/notes.py reply <角色> <动作> "改了什么"   # 回复并标为已处理（页面上立刻显示）
```

每处理一批留言，把其中反映出的**口味**（不是单个数值）提炼进记忆 `move-preferences`：例如“蓄力普遍嫌长”“白光要克制”“神要有威压、不弯腰”。之后调别的角色先按这些口味来，不必等用户逐个指出。“满意”的动作同样是信息：记下它的参数范围，作为同类的基准。

1. 用户说的是招式单里的词：阶段名、特效名。说不清时请用户标记那一刻。
2. 一条意见对应尽量少的数。这一类角色都要改时改原型，不要逐个改。
3. 改完先跑自检，再让用户看；用户看到的应该是值得判断的版本。
4. 现有元素调不到的效果（新的形状、新的镜头）才去改 `skillfx.js`，并在第 2 节的表里登记新元素。
5. 改动不改变规则状态；卡名、费用、攻血仍是 DOM。

## 7. 现状与已知问题（2026-10-02）

- 70 个角色（54 个人形、16 个兽类）、14 个原型，由原来 `models.js` 里的两张表迁移而来。迁移后的编译结果与原表逐项相同，阶段边界取整到毫秒（最大偏差 0.5 ms）。
- 迁移时修正：伊芙的套件原先被误写在艾达的招牌里，从未生效；现在是她自己的。
- 迁移时去掉的无效字段：龙与阿什拉（远程）的 `windup`、`leap`、`dash`，荆棘树灵（原地出手）的 `leap`、`dash`，都没有代码读取。远程兽类的出手前摇现在由招式单的 `draw` 给出（数值与原来生效的相同）。

### 第一轮自审（2026-10-02）改了什么

引擎（所有角色受益）：

- **定帧停在命中姿势上**（`arena.js` `land`）：命中信号比动作到位早约一帧，定帧会把武器冻在离对手一步远的地方；现在定帧开始时把动作对到命中帧。
- **动作播完后回位不再瞬移**：动作片段比回位先结束时，角色会一帧跳回原位（绵羊最明显）；现在保留回位的那一跳。
- **武器瞄准不再一帧翻转**（`models.js` `aimBlade`）：两种握法都能对准目标时，会在相邻两帧之间切换，剑身翻 120°（侍从的胜利动作）；现在沿用上一帧的握法，按手腕的速度转过去。
- **地面法印不再画在角色腿上**（`skillfx.js`）：地面贴花改为受角色遮挡。
- **新的瞄准方式 `aim: { attack: "foe" }`**：挥砍的最后一段把武器带到对手身上。高个子的平砍原来从矮对手头顶扫过（白霜之王离对手 0.6 个身高、收割者 0.3、索拉 0.26）。

招式单：

- 命中帧对到武器真正打到对手的那一帧：剑盾原型 19→20、侍从 20→18、狂战士 25→26.5、收割者 25→27.5、刺客 30→26、重拳原型 8→10、守灯巨兽单独 21。
- 站位：徒手的四位（守根人、红围巾、艾达、琥珀之躯）和刺客站得更近；兽类按模型实测设置停步距离（原来用体素造型的距离，写实模型的身体长得多，狼、守灯之兽、鹿、凤凰等会把半个身子穿过对手）；狼骑、新兵、古木、山岳、重拳原型微调。
- 新兵恢复站姿（原来单膝跪进对手身体里，剑穿过自己的大腿）。
- 娜希拉（和镜中的娜希拉）：放大镜在右手，原来的片段却是左手施法、左手举起；改为镜像片段。
- 菲德莉亚：胜利动作是握拳，剑垂在身侧，天光却打在剑尖上；去掉天光。
- 凤凰：命中的新月和火焰缩小（原来把对手整个罩成白球）。
- 根母：补上招牌（她是唯一没有招牌的人形，命中时用的是旧的像素火花）。
- 拾珀人、黑肺：造型借自亡者织梦师，继承了“远程”，套件却是近战横扫，实战里原地横扫同时飞出一发弹；现在是近战。
- 艾达、琥珀之躯、红围巾、倒影军团：造型借自圣骑士，重击时会连带降下圣骑士专属的天剑；已去掉。

### 第二轮（2026-10-02，用户反馈：弓拿反、白光偏大、锥体粗糙）

- **罗温（和镜中的罗温）的弓拿反了**：模型做出来就是弦朝对手、弓背朝自己。`models.js` 的 `TURNED` 表在载入时把他左手握着的弓绕自身长轴、以握把为中心转半圈（`turnHeld`）。薇丝珀的弓是对的。以后再有持物朝向做反的模型，加进这张表。
- **命中白光收敛**（70 个角色平均：对手被过曝盖住的面积，峰值 26% → 11%，150 ms 后 12% → 4%）：
  - 命中闪光的光球、星芒、横向光条都缩小、变暗、变短；冲击环变细变暗；光柱变细，亮度约减四成。
  - 刀痕从"中间带一团光的光条"改成干净的一道切痕，并缩短；新月刀痕缩小。
  - 受击者自己的闪白：写实角色整体闪白的时长从 11 帧减到 7 帧、强度约减半；被招牌招式打中时不再叠加第二团光。
  - 法术弹的落点爆发：火团更少、更小、更快散开。
  - 霜冻地面、落点法印、奥瑞恩的日印与地裂都压暗，只留纹路。
  - 神的贯穿光痕：原来整条带子在光头经过时全白（"硬边白带"），现在光只沿着痕迹本身走，并用元素色而不是白芯。
- **地刺与碎石重做**（`skillfx.js` 的 `SOLID_VS/FS`）：不再是六棱锥。
  - 冰：水晶——直棱柱、不等宽的面、带肩的尖顶，边缘发光、带高光。
  - 岩：石笋——粗壮、每一面和每一层都不规则，深色石头，根部透出元素色的热光。
  - 荆棘：细长、弯曲、带棱，尖端变深。
  - 每根大刺脚下带一两根小刺成簇；碎石是棱角不规则的石块。每个面有自己的明暗，底部在阴影里。
