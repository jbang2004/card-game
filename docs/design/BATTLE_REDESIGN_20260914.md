# 战场视觉与交互重构设计 · 2026-09-14

> 状态：**提案，待用户拍板**。依据：代码审计（`src/mobile-view.js`、`src/presentation/battle.css`、`src/ui.js`、`src/presentation/hand.js`）与 7 个视口的实测截图（`output/battle-audit-20260914/`，脚本 `capture.cjs`，数据 `metrics.json`）。

## 0. 一句话结论

战场目前是「一套 1600×940 桌面坐标 + 手机端用 JS 内联盒子硬挤」的产物：随从尺寸由「arena 剩余高度」反推，英雄卡、技能、契约、提示条各占一块固定区域，互相抢空间。重构的核心不是调数值，而是换模型：**英雄收成一条"指挥台"，手牌改成"半隐藏扇形坞"，把省下来的整块高度还给随从**，再用同一套状态机统一鼠标 / 触屏交互。

## 2. 设计原则

1. **战场是主体**：随从与手牌的可读性优先于任何 HUD。HUD 只能占「条」，不能占「块」。
2. **英雄是指挥台**：头像、血/甲、武器、技能、契约、法力属于同一个组件，永远相邻；敌方指挥台是它的只读镜像。
3. **一套状态机、三种形态**：idle → inspect → armed → targeting → resolve 在鼠标和触屏上是同一套，只有触发方式不同。
4. **信息分层**：牌面常驻只保留「费用 / 名字 / 攻血 / 关键词图标」，规则文本进 inspect 层；场上随从用"战场令牌"而不是缩小的手牌。
5. **尺寸随数量而不是随上限**：3 个随从就该有 3 个随从的大小，7 个时再收紧并允许叠放。

高度预算（390×844，安全区另计）：48 + 56 + 400 + 72 + 120 = 696，剩 ~150px 缓冲给安全区与行间距。**arena 从 182px 变成 ~400px**，随从行高从 91 变成 ~190。

| n | 令牌宽×高（390 宽） | 说明 |
|---|---|---|
| 1–3 | 96×120 | 约为现状 65×79 的 1.5 倍面积 ×2.2 |
| 4 | 84×105 | |
| 5 | 70×88 | |
| 6–7 | 58×72，相邻叠放 −10px | 点击该行任一令牌 → 该行"展开"成可横滑的 96px 卷轴（0.2s），点空白收起 |

360 宽走同一公式，1–3 个时 88×110，不再出现 38×46 的断崖。

左栏 96px 放上下两个竖排指挥台（圆头像 48 + 两枚芯片 + 法力点阵）；右栏 120px 放技能 / 契约 / 结束回合，**三者纵向对齐我方指挥台的水平线**（技能节点中心与我方头像中心同 y，中心距 ≤ 视口宽 × 0.85 但视线只需横扫一次，不再上下跳）。844×390 时 arena 高 ≈ 390 − 40 − 96 = 254，行高 ~120 → 随从 1–3 个时 88×110（现状 46×56）。

### 3.3 桌面（W ≥ 1360 且 H ≥ 700）

保留 T5 场景页与 1600×940 逻辑画布，但：

- 我方英雄改为**指挥台组**：头像卡（固定 156×231，不再跟随手牌宽）右侧紧贴一列：技能节点 56 → 契约芯片 → 武器槽 → 法力点阵；右下角只剩「结束回合」+ 牌库计数。技能↔头像中心距从 1424px 降到 ~140px。
- 敌方英雄同样在头像右侧挂契约进度与武器，不显示法力。
- 手牌：默认露上 55%（费用 / 插画 / 名字可读），hover 该卡抬起到 100% 并放大 1.12（`translateY(−90px) scale(1.12)`，180ms），相邻卡让位 24px；鼠标离开 240ms 后回落。10 张时改叠放而不是缩到 95px。
- 随从行：以 arena 中线为轴，随从 116×146 → 在 n ≤ 4 时放大到 132×166，n = 7 时回到 116。
- `#card-preview` 从固定左侧改为**锚定在被悬停元素旁**（右侧优先，越界则翻到左侧），手牌卡的 hover 已经抬起，不再需要 preview。

### 4.2 战场令牌 `.minion`

- 比例 1:1.25，插画 `object-fit: cover` 取头部构图；攻 / 血徽章在底部两角，字号 = 令牌宽 × 0.22（58px 时 13px，96px 时 21px）。
- 关键词（嘲讽 / 圣盾 / 冻结 / 复生…）改为顶部一排 14px 图标，不再显示文字。
- 状态：可攻击 → 底部 2px 蓝色呼吸线；已行动 → 插画降饱和 40%；合法目标 → 现有准星；被选中 → 抬起 6px + 外发光。
- inspect：长按 / hover 440ms → 在令牌上方弹出完整卡面（宽 `clamp(190px, 52vw, 300px)`），锚定令牌而不是屏幕中央；桌面 hover 同理。

### 4.3 手牌坞 `.hand-dock`

- 坞高：竖屏 120、横屏 96、桌面 128（露出比例 40% / 45% / 55%）。
- 排布：扇形叠放，卡宽固定（竖屏 112、横屏 96、桌面 156），步进 = `min(卡宽 + 12, (坞宽 − 卡宽) / (n − 1))`，10 张也不横滑；坞外 8px 渐隐遮罩表示"下面还有"。
- 触屏手势：
  1. 按下并**横向**滑过坞 → "拨牌"，手指经过的卡逐张抬起 12px（触觉反馈），松手时指下那张进入 **armed**：升到坞上方完整显示（放大到 1.0，其余卡回落，坞变暗）。
  2. armed 态下：向上拖 > 40px 进入 **targeting / 落位**（沿用现有 `unitAt()` 与瞄准线）；点击 armed 卡本身 = 快捷打出（无目标牌）；点空白 / 向下拖回 → 取消。
  3. 长按 440ms 不动 → **inspect**（居中大卡，现状逻辑），松手回落。
  4. 法力不足的卡：费用徽章变 ink-3，armed 时坞上方显示「缺 2 点法力」小芯片，不弹 toast。
- 鼠标：hover = 抬起并放大（等价 armed 预览），按下拖 = 拖拽出牌（现状），点击 = 现状 `selectCard`。
- 敌方手牌背面不再渲染（三种形态都隐藏），改成敌方指挥台上的 `🂠 6` 芯片。

### 4.4 提示与反馈 · 四条通道

| 通道 | 用途 | 位置 | 文案规则 |
|---|---|---|---|
| 目标层 | targeting 时 | 非目标降暗 35%，合法目标准星，瞄准线；**不再有整条提示带** | 只在 armed 卡上方显示 12px 芯片「选择目标」；取消按钮跟随卡片右上 44px 圆 |

### 4.5 结束回合与回合状态

- 结束回合始终在我方指挥台所在的水平线上，右端；可出牌 / 可攻击时按钮呼吸蓝光，无可用动作时变为「结束回合 ▸」实心态。
- 回合芯片保持顶栏居中；敌方回合期间整块 arena 加 2px 红色上边线代替全屏遮罩。

## 5. 交互状态机（统一）

```
idle ──hover/拨牌──▶ armed ──拖>40px / 点目标──▶ targeting ──松在合法目标──▶ resolve
 │                    │                            │
 │  长按/右键          │ 点空白 / 拖回 / Esc          │ 松在非法处：气泡拒绝，回 armed
 ▼                    ▼                            ▼
inspect ◀── 松手 ──  idle                         idle
```

- 与 `docs/design/HAND_GESTURES.md` 的差异：新增 **armed** 中间态（解决"点牌直接跳目标态、无选中反馈"），拨牌代替横滑。拖拽释放仍是确认动作，非法释放仍回手且不扣法力。
- 随从攻击：点 / 拖己方可攻击随从 → 同一 targeting 态，目标层同样处理。
- 输入模态由 `pointerType` 决定文案与触发时长，不再由 `body.touch-layout` 决定。

## 6. 断点与实现架构

### 6.1 形态判定（替换 `mobile-view.js:33-38`）

```
form = H >= W                    ? "portrait"
     : (W < 1360 || H < 700)     ? "landscape"
     :                             "desktop"
input = pointerType (coarse/fine)，与 form 正交
```

`compactDesktop` 不再等于触屏：1280×720 鼠标窗口得到 landscape 形态 + fine 输入（hover 生效、44px 命中区不强制）。

### 6.2 几何来源

- **竖屏 / 横屏改为 CSS Grid + 容器查询**（`grid-template-rows: 48px 56px 1fr 72px 120px`），元素归位到语义容器（`.hero-console.enemy`、`.arena`、`.hero-console.player`、`.hand-dock`），JS 不再对英雄、技能、契约、提示条写 `left/top`。
- `mobile-view.js` 保留三件事：随从令牌尺寸档位与 x 坐标（读 `.arena` 实测尺寸）、`EmberViewport.pos/lane/deckAnchor` 给动画用、`--scale` 桌面画布。`lane()` 的桌面兜底改为读实测行中心（现状 374/554 与真实 295/459 差约 80px）。
- 桌面保留 1600×940 画布，但 `battle.css` 只留一套几何（清理 R7），英雄尺寸与 `--battle-card-w` 解绑（R6）。
- 尺寸令牌进 `skins/slate/base.css`：`--hud-console-h`、`--hand-dock-h`、`--hand-peek`、`--token-w-{1..7}`（token candidate 先写字面值）。

### 6.3 DOM 调整（`src/template.html:66-72`、`src/ui.js:733-775`）

```
#battle
  .hero-console.enemy   ← #enemy-hero 内容 + 契约进度 + 敌方手牌计数
  .arena                ← #minions（不变）+ 横幅浮层 + 目标层芯片
  .hero-console.player  ← #player-hero 内容 + #power-btn + #contract-open + #weapon-slot + .mana-panel + .turn-controls
  .hand-dock            ← #hand（不变）+ #touch-cancel
```

`#power-btn` / `#contract-open` 保持 id 与事件，只换父节点；`contracts.js:151-175` 的 `render` 不需要改。

## 12. 第三轮设计 · 参照万象棋的一致性与神卡舞台（2026-09-14，提案）

用户给出万象棋（横屏自走棋）的战场截图作参照。可借鉴的不是它的布局本身（它只有横屏一种形态），而是四条原则：

1. **HUD 只有一套零件，任何尺寸都不换零件**：圆头像 + 名字 + 数值条、黑底大数字芯片、角落大圆钮。屏幕变小只改几何，不改身份表达。
2. **无框浮置**：所有 HUD 直接浮在场景上，靠投影和半透明深色芯片分层，没有一个面板框。棋盘占约 70%。
3. **数值一眼可读**：单位头顶是一个大号黑圆数字 + 细血条，敌我用条色区分（红 / 蓝），不靠位置。
4. **主操作在角落**：右下角一个大圆钮承载本回合的核心资源（⚡6 / +12），左下是自己的身份。

### 12.1 大小屏一致性：英雄用同一张卡，三种尺寸

现状：桌面是 156×231 的英雄卡，手机是 56px 圆头像，两者是两种零件。改为**同一张英雄卡的三档缩放**，圆头像仅在 320 宽以下退化使用：

| 形态 | 英雄卡 | 摆法 |
|---|---|---|
| 桌面 | 156×231（不变） | 左栏，技能节点 / 神卡槽位贴右侧 |
| 横屏 / 平板 | 72×106 迷你卡（保留名牌与攻血徽章，字号按 cqw 缩） | 左栏上下各一张，技能节点贴右侧，芯片在卡下 |
| 竖屏 | 60×89 迷你卡，**上沿伸出指挥台带 12px**（像从带子里探出的名牌） | 指挥台左端，右侧技能节点、名字、血甲芯片 |

指挥台去掉底板矩形，改为无框浮置：芯片、迷你卡、技能节点直接落在场景上，靠 `0 10px 30px #0008` 投影和芯片自身的深色底分层（万象棋原则 2）。敌方指挥台同理。

### 12.2 悬停展开与触屏等价手势：按输入而不是按布局

`hover:hover and pointer:fine` 命中时（鼠标，无论窗口多小），手牌坞的 hover 抬起 + 放大照常生效；`pointer:coarse` 时，拨牌 = hover 的等价物：**手指按住并横向滑过坞，指下那张整张升出坞外并放大到 1.0**（现在只抬 12px），松手即选中，手指离开坞则回落。这样小窗口鼠标用户和触屏用户都得到「不点击也能看清」的体验。在 `mobile-view.js` 写入 `body.pointer-fine` / `body.pointer-coarse`，CSS 用它而不是 `touch-layout` 决定 hover 规则。

### 12.3 神卡出场编排（更灵动）

1. 按下槽位：卡背下压 0.97，松手回弹 1.05 并闪一次金边（80ms）。
2. 起飞：沿轻微弧线飞向中心，`rotateY 180→0` 同时 `rotateZ −8°→0`，缩放带 1.04 过冲再回落（弹簧曲线 `cubic-bezier(.34,1.4,.64,1)`，总时长 0.55s）。
3. 翻面中点（0.27s）：一道金色高光从左上扫过正面（`::after` 线性渐变 + `mask`），同时暗幕模糊从 0 升到 8px。
4. 落定后：卡面随指针 / 手指位置做 ±6° 的 3D 视差倾斜；仪式区文字从下方 16px 处逐行浮现，每行错开 60ms。
5. 关闭：0.3s 反向飞回槽位并翻回卡背。`reduced-motion` 或「减少动态效果」→ 0.2s 淡入淡出。

### 12.4 仪式区去框，改为版式

不再有面板底与边框，只用文字层级与一条细线：

```
              [ 大卡 ]
        神祇契约 · 9 法力            ← 12px 小号大写风格眉标，ink-3，字距 2px
   星火 · 成功施放六种不同名称的法术   ← 15px ink-2
   ────────────────────── 4 / 6      ← 2px 进度线贯穿整行，数字右对齐，白色
   星火箭 · 寒霜之触 · 星界密卷 · 冰封领域 · ○ · ○   ← 已施放白字，未施放 ink-3 空心点
              [ 唤醒 · 烬辰 ]         ← 唯一的实体：主药丸 48px
              敌方公开契约            ← 纯文字链 ink-3
```

桌面与横屏平板改为**左右两栏**：大卡在左，仪式版式在右（像博物馆说明牌），列宽 340 + 360，垂直居中；竖屏保持上下。

### 12.5 三张神卡：Coverflow 为默认，桌面可并排比较

- **竖屏 / 横屏手机**：Cover flow。焦点卡居中全尺寸，左右两张以 0.62 缩放、−16% 透明度露出边缘（可点、可横滑切换，带 snap），仪式版式跟随焦点卡。这样一眼看出「还有两张」，一次手势切换。
- **桌面 / 平板**：三张等尺寸并排（3×240 + 间距，1600 宽有余），焦点卡抬起 12px 并带金边，其余降亮 0.75；仪式版式在焦点卡下方（并排时不用左右两栏）。hover 切换焦点，点击固定。
- 槽位内仍是紧凑叠放 + 数量角标；点开时三张从叠放处**依次**起飞（错开 70ms），到位后再展开为上面两种排布。

### 12.6 从万象棋直接借的两处小件

- 顶栏中央的回合芯片改为「第 7 回合 · 34s」式样的**圆角胶囊 + 敌方回合时红色细边**，与万象棋的顶中计时一致。
- 触屏结束回合改成右下角 **64px 圆钮**（万象棋的 ⚡ 位），法力 `6/6` 以小字贴在圆钮上方；指挥台右端腾出来给名字与芯片。

实施顺序建议：12.2（输入判定，最影响体验）→ 12.4 + 12.3（舞台版式与编排）→ 12.5（三张）→ 12.1（英雄卡三档）→ 12.6。

## 13. 动效与美学审计 · 第三轮补充（2026-09-14，提案）

### 13.1 已知缺陷：神卡舞台的退场不同步

点暗幕关闭时，卡先飞回槽位，仪式区随后才淡出。原因是两者各自有过渡（卡 0.3s 飞行，仪式区跟着 `.god-stage` 的 opacity 过渡在卡结束后才触发）。规则：**一组元素同进同出，共用一条时间线**。关闭时 t=0 同时开始：卡 0.3s 飞回并翻面、仪式文字 0.15s 淡出并下沉 8px、暗幕模糊 0.25s 从 8px 归零，veil 0.25s 淡出；进场时也一样，仪式文字在卡起飞后 120ms 开始逐行浮现，而不是等卡落定。

### 13.2 动效令牌（全战场统一）

现在每处过渡各写各的（手牌 0.18s、舞台 0.45s、呼吸 2.2–2.4s）。收成一组令牌放进 `base.css`：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--m-fast` | 120ms | 芯片数值变化、hover 让位 |
| `--m-base` | 180ms | 手牌抬起、选中、令牌高亮 |
| `--m-stage` | 320ms | 浮层进出、随从落场 |
| `--m-cine` | 550ms | 神卡出场、降临仪式 |
| `--e-std` | `cubic-bezier(.2,.8,.2,1)` | 进场 |
| `--e-spring` | `cubic-bezier(.34,1.4,.64,1)` | 带过冲的落定 |
| `--e-exit` | `cubic-bezier(.4,0,1,1)` | 退场，加速离开 |

规则：退场时长 = 进场的 60%；同组元素共用一条时间线；`reduced-motion` 与游戏设置下全部退化为 0.2s 淡入淡出。

### 13.3 战场（arena）

- **落位插槽可见化**：拖牌进入落位模式时，地面浮现七个淡淡的圆形位标（万象棋地面就有），随从之间**打开一道缝**表示插入位置（拖到两只随从之间时它们各让 12px），松手落在缝里。需要 `play` 动作支持落位索引；若引擎只支持追加，则只在末尾显示一个位标，不做假缝。
- **令牌降噪**：宽度 < 90px 的令牌隐藏「随从 · 中立」职业带，只保留攻血徽章与关键词图标；> 90px 时职业带改为 9px 大写风格。
- **可攻击态**：现在是一个小点；改为令牌描边蓝光 1.6s 呼吸 + 整卡 2px 上下浮动，敌方回合停止。
- **瞄准**：瞄准线改为 3px 渐变实线 + 发光线头跟随指尖；进入瞄准时非法目标降亮到 0.35（现在只高亮合法目标）。
- **回合切换**：敌方回合 arena 上沿 2px 红色细线渐显，结束回合钮文字改「对方思考中」并带 12px 转圈；轮到我方时法力点阵从左到右逐颗点亮（每颗 40ms），提醒资源刷新。

### 13.4 指挥台与数值

- 血量芯片数值变化用**滚动数字**（120ms），受伤时芯片闪红一次、治疗闪绿一次；护甲芯片出现 / 消失用 scale 0.6→1 弹入；敌方手牌数变化时芯片轻弹一下。
- 芯片内数字统一 `tabular-nums`，手机最小 12px；技能节点费用角标在法力不足时变 ink-3 而不是整个节点变灰（节点保留图标可辨认）。

### 13.5 手牌坞

- `hand-fits` 时给扇形加 ±3° 的物理旋转与 2px 弧度（现在是平铺叠放），拨牌抬起时旋转归零。
- 回合开始法力增加后，**刚变得可打出**的牌在坞里闪一次白边（一次性，600ms），减少「能出什么」的扫描成本。
- 拨牌换卡时触发 `navigator.vibrate(5)`（若设置允许），合法落位 `vibrate(12)`。

### 13.6 颜色语义收敛

现在同时存在：可打出 = 绿描边、可攻击 = 蓝、合法目标 = 橙 / 金、神 = 金、错误 = 红。收成三条：**蓝 = 我方与可交互**，**金 = 目标与神圣**，**红 = 敌方与危险**；「可打出」改为白色细边光（不再引入绿），错误提示保留红。

### 13.7 桌面顶栏

品牌字标 + 5 个图标 + 回合芯片 + 两个文字页签 + 牌库计数挤在一行。建议：「战斗记录」「首领情报」改为 36px 图标药丸（与音量 / 设置同语言），牌库计数并入英雄卡旁的小芯片，顶栏高度 48 不变但留白翻倍。

优先级：13.1（缺陷）→ 13.2（令牌，后续所有动效的基础）→ 13.3 瞄准与回合切换 → 13.4 → 13.5 → 13.6 → 13.3 落位插槽（依赖引擎）→ 13.7。

### 14.3 测试调整（设计有意改变的断言，逐条写明原因）

- `responsive-component-style`「shared components keep one material contract」：
  从共享材质清单里移除 `#end-turn` 与 `.hero`——**原因**：§12.1 让触屏指挥台变成无框
  浮置（卡 / 芯片 / 技能节点各自带投影，不再共用底板），§12.6 让触屏结束回合变成
  64px 圆钮而桌面仍是药丸。两者仍是**同一个组件、同一套状态**，只有外壳按布局不同；
  这份清单表达不了「同组件、分布局外壳」，硬对齐就等于撤销这两条设计。牌面、法力面板、
  技能节点、工具药丸仍在共享材质合约内。
- `ui-alignment`「ornaments and HUD stay anchored」：法力面板里 `6/6` 与点阵的**先后
  顺序**不再规定（原断言要求点阵在数值右侧）——**原因**：§12.6 把 `6/6` 移到点阵右侧，
  贴着角落的圆钮当它的说明。断言要守的契约（数值与点阵同一行、都在面板内、彼此垂直
  居中）原样保留。
- `card-reading`「hand rail keeps compact rules complete」与「opening hand and battle
  hand keep one card aperture」：改用 `offsetWidth/offsetHeight` 而不是
  `getBoundingClientRect()` 量卡与卡图——**原因**：§13.5 给扇形加了 ±3° 旋转，旋转元素
  报的是**轴对齐外框**，宽高比与高度都会随卡在扇形里的位置变化。这两个断言要守的是
  卡的**布局**几何（一张卡图在任何手牌里同样大 / 起手与战场共用一个卡窗），布局盒正是
  它的正确量法。
- `hand-drag`「horizontal panning on a card still scrolls a full hand」：`fits` 分支从
  `scrollWidth === clientWidth` 放宽到差值 ≤ 8px——**原因**：同上的旋转外框。装得下的坞
  是 `overflow: visible`，根本不是滚动容器；多出的几 px 是画出去的旋转边角，不是轨道。
- **不是测试调整而是源码修复**（记下来以免下次又踩）：`combat-motion`「freeze settles
  without lingering ice particles or delayed filter transitions」一度失败，原因是
  §13.2 令牌化时把 `transform` / `filter` 过渡加到了 `.minion` 上，而
  `legacy-components.css` 的「FLIP / combat owns movement」刻意只给 `.minion` 留
  `box-shadow` 与 `border-color`。已改回只令牌化这两条（那里的 120ms 正好是
  `--m-fast`）。同理 `mobile-view.js` 的 `handCardAnchor` 把横向容差放宽到
  `ceil(height×0.06)+1`，否则扇形两端被旋转撑大的外框会被判成 clipped，抽牌飞行整个
  跳过（`card-motion` 的 draw handoff 会失败）。

### 14.4 妥协与未尽事项

1. **落位插槽只有行末一个**（原因见 §14.1 表格最后一行）。要做到设计里的七个位标 + 开缝
   插入，得让 `play` 动作带落位索引并改 `summon` 的 `board.push`，那是规则层改动，
   超出表现层任务的边界。
2. **迷你卡上没有攻血宝石**，攻击 / 生命仍是卡右侧的芯片。把它们画到卡上要在 `ui.js`
   里改 DOM 父子关系（现在它们在 `.hero-chips` 里，而 `.hero-chips` 是定位祖先），
   而桌面与旧版徽章是按 `.hero` 的百分比定位的，`ui-detail` / `ui-alignment` 正盯着
   这套几何。芯片 12px 在迷你卡旁已经清楚可读，这是 §12.1 真正要的结果。
3. **桌面 hover 仍按布局键控**（`body:not(.touch-layout)`），没有改成 `pointer-fine`。
   桌面实际上恒为精确指针，改键控只会给 `card-reading` / `game` 增加回归风险而没有
   收益；§12.2 真正缺的那一半——**触屏布局下的鼠标用户**——已经补上了。
4. **横屏迷你卡是 56×83 而不是 72×106**，当 `H < 470` 时。390 高的横屏装不下两张
   106 高的卡加两条芯片行加手牌坞（可用轨高只有 230）。平板横屏（1024×768）拿到
   完整的 72×106。
5. **`6/6` 在圆钮左侧而不是正上方**（竖屏）。§13.3 的法力点阵逐颗点亮必须和数值在
   一起，96 高的指挥台带放不下「点阵 + 数值」再叠一个 64px 圆钮；现在数值右对齐，
   正好落在圆钮旁边当它的说明。
6. **320 宽按「320 及以下」处理**（仍用圆头像），设计文字是「320 宽以下」。320×568
   是回归测试视口，把它留在已验证的圆头像路径上更稳妥。
