# 参考复刻视觉规范

> 磨砂青岩（slate）是唯一表现层，没有皮肤开关；令牌、组件语言与各页简报见 [SLATE_DESIGN_SYSTEM.md](SLATE_DESIGN_SYSTEM.md)。本页保留跨版本通用的复刻方法与响应式约束。

适用于当前 Emberfall UI。新参考图或用户明确选择可改变视觉方向；以下是项目约定与已验证的方法，不是所有页面必须复制主页的模板。技能入口：`.agents/skills/reference-page-recreation/SKILL.md`。

## 组件与材料

| 层 | 当前方法 | 选择依据 |
| --- | --- | --- |
| 场景 | 主题语义角色绑定现有原画，Canvas 缓存绘制 | 优先匹配构图，避免背景里烘焙 UI |
| 药丸按钮（无位图） | 纯 CSS 药丸：主 = 蓝色渐变，次 = `--slate-pill` 深底 + 细边 | 位图按钮皮肤已删除，光晕留白问题随之消失；主/次按钮共用一套高度与圆角 |
| 简单标志 | `EmberArt.icon` 原生 SVG，currentColor 或有限银蓝实色面 | 避免字体箭头基线偏差；无需额外图标库 |
| 字体与文案 | 当前 `--ui-font` / `--ui-display`，实时 DOM | 不提交字体；字标与正文分清视觉层级 |
| 颜色 | slate 令牌（`skins/slate/base.css` 的 `--slate-*`） | 页面文件不重定义令牌；手机复用同一套材料，断点主要调整几何 |
| 浮层壳 / 页面壳（无四角 SVG） | 统一 `--slate-material` 磨砂底：全屏功能页用页面壳（满屏、左上返回箭头），叠在场景上的用浮层壳（圆角 16、细边、投影、右上圆形关闭） | 两套外壳按 `[data-dialog-size]` 区分，由 base.css 统一提供；分节用 1px 发丝线。四角 SVG 装饰与玻璃底已从代码中删除，不要重新引入 |
| 状态与交互 | 既有应用动作与只读状态 | 皮肤不承担规则，不因视觉特效改存档 |

## 图标与排版

先看原图局部，再画结构。用填充的刃面/晶面与少量轮廓区分材质；不要把大图细节全部压进小图。主操作与页脚可共享结构但使用不同细节密度。保持真实透明，调色优先 currentColor，不依赖对位图反色来修风格。

顶栏是导航标识，主标题是视觉主体；避免两处重复同一复杂 Logo。同组按钮的图标、文字和箭头使用共同对齐轴；清除旧 SVG 绝对定位。圆形箭头容器等宽高，检查实际路径与圆心，不能只看文字行高。

收藏展示可用不同高度、轻微倾角与阴影表达前后关系；不机械平铺，也不为追求层次遮住标题。为箭头单独留列/内边距，按**变换后的卡片边界**检查间隔。主页目前采用至少 12 CSS px 的实测间距；这是主页验收值，新页面按实际尺寸选择，不机械套用。

## 动态与触控

选中指示是所在组件自己的下划亮条（`.nav-link.active::after`、`.filter-btn.active::after`）；旧主题那条跟随指针的共享移动光带已经删除，不要重新引入——指示只表达「哪一页/哪一项是选中的」，悬停与焦点用颜色反馈。桌面缩放平面内使用一致的布局坐标，不混用缩放后的 viewport 坐标。

按钮按下、hover、focus、disabled 有明确反馈；遵从游戏与系统的减弱动态偏好。触控操作尽量至少 44 CSS px，保留安全区。手机独立排版，空间不足时先压缩装饰，不挤压主要操作；不把桌面整体缩小当作手机方案。

## 组件归属与响应式

非全屏面板由 [共享面板组件](SHARED_PANELS.md) 提供外壳和留白；普通弹窗自动接入，全屏页只接入内部参数面板。页面代码不重新声明同一面板的底色、圆角和四边内边距。各断点只负责重排与可达的滚动区域。

修正错位前先确认样式加载顺序、最终生效声明和祖先变换，追踪旧的 absolute、inset、margin、固定高度及宽泛 span/svg 选择器。组件职责遵循 `legacy → layout → theme → components` 层级；在已有归属处修改，并删除被替代的专属声明及未执行的实现。不要以追加高优先级选择器代替定位原因。基础、状态和响应式规则可以分开；同一状态和尺寸下，同一属性不应由多处互相争夺。相似外观不足以证明应抽象，重复的结构、行为与约束才是共享组件的依据。

同一组件在桌面、短横屏和小竖屏只允许改变位置、尺寸、间距、排列、可见性及必要的字号密度；背景、边框、圆角语义、阴影、裁切形状、字族、字重和状态反馈必须由共享组件层统一提供。`polish-desktop.css` 与 `polish-mobile.css` 只负责布局，不建立第二套皮肤（`tests/theme-presentation.test.cjs` 逐条校验这两份文件不含材质声明）。新增或修改跨尺寸组件后运行 `tests/e2e/responsive-component-style.spec.cjs`，比较真实流程中默认、选中、激活和禁用状态的计算样式；允许按布局隐藏节点，不允许同一可见节点因视口更换材质。

文字、图标、照片和装饰分别拥有布局空间。按钮文字居中与“图标加文字整体居中”是不同要求，应按实际意图选择；本项目主要操作采用独立文字槽和侧边图标槽。头像的裁切与选中状态分开表达，避免在照片上叠加内边距、描边和缩放。品牌、标题和关闭按钮各自保留安全间距。装饰位图的光晕或透明留白不作为文字可用空间。

战场指令和错误反馈共享独立预留区域，同一时刻只显示一种；取消操作使用可见文字与至少 44px 命中区。辅助入口可用图标文字和细线，不能把复杂纹理作为所有按钮的默认要求。

空间不足时先减少装饰、重排按钮与列数，或进入明确的滚动区域；不以不断缩字或缩小点击面积维持桌面构图。数字字号随所在组件的密度确定，不直接继承大型展示数字样式。长列表负责滚动，关键操作保持可达，图表保留完整绘图区与标签空间，不能被 flex 压缩成碎片。短横屏可以改变图表的固定/滚动归属；保留同一份状态与节点，不复制第二套交互实现。

图标先保证小尺寸语义，再补充材质。本项目法力、攻击、生命和耐久分别采用晶体、动力拳套、心形和盾形轮廓；不能只靠颜色区分四种相同徽章。简单语义图标用 SVG，复杂裂纹与反射用位图，数值继续使用实时 DOM。当前属性徽章复用半包围演示页确认的渐变、轮廓和切面；每实例 SVG 定义使用独立 ID。

## 实装验收

容器可见和可点击不足以证明排版合格。先按实际窗口尺寸检查整体，再局部放大检查轮廓与透明边缘。根据本次变更验证以下关系：

- 用真实文本 Range、图标路径与变换后的装饰边界检查留白、居中偏差、基线和间距；显式隐藏的装饰不参与可见几何测量。
- 检查图表绘图区与标签完整性、数字可读性、标题和关闭控件的间隔，以及需要等尺寸的操作组是否一致。
- 覆盖用户报告的中间窗口尺寸及相关断点两侧，补充小竖屏、短横屏和旋转；不能只用标准桌面/手机预设代替实际问题尺寸。
- 检查 hover、pressed、focus、disabled、动态文案及长内容；状态更新后图标、文字槽与焦点仍然保留，操作可以真实触发。
- 检查透明边缘在浅底、深底与实际背景下的表现；确认装饰入口与导航连接真实流程。

优先扩展既有检查器中的行为约束，不为每个页面复制一套固定坐标断言。可复用入口是 [内容几何检查器](../../tests/e2e/helpers/visual-discipline.cjs)，牌组与旋转案例见 [组件回归](../../tests/e2e/component-discipline.spec.cjs)，头像与窗口尺寸案例见 [视觉纪律回归](../../tests/e2e/visual-discipline.spec.cjs)。测量阈值按组件用途确定，具体数值与视口放测试和页面档案。

修改源码后构建，执行与变更相关的规则、素材及浏览器检查。文档修改只做文档校验。最终保留实装截图审美检查：自动测试只能证明已测约束，不能证明视觉和谐或像素一致；手机模拟不能称为实体手机验收。

## 经验维护

经验只维护一份主要归属：跨页面原则放本规范，具体坐标、素材、被否定方案及取舍放 [页面档案](reference-pages/INDEX.md)，可测故障放已有回归，技能保留检查时机和执行方法。更新已有条目，避免按轮次累积重复清单。测试结果写明对应迭代、范围与未覆盖项；局部组件清理完成不代表整个样式库没有重复。
