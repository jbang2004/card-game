# 游戏命名方案（待决策）· v0.14 诸神同辉

## 结论（第四轮修订）：`鎏金 / 流金` 判定为俗气；放宽撞名标准

用户判定 `流金` 俗气。**成立**：`鎏金 / 流金` 是楼盘、会所、KTV 的高频命名用词（鎏金公馆、流金水岸、流金岁月），带商业装饰味；我此前说"原字 `鎏金` 最美"属品味误判。整条"华丽装饰词"路线（鎏金、流金、烬火）就此作废。

**同时修正一条我定得过狠的标准**：前几轮把"任何撞名"都当成否决条件。实测这是死路——有中文美感的 2–4 字词几乎全被用过：

| 备选 | 占用 |
|---|---|
| 守灯人 | [The Lightkeeper，哥特恐怖游戏](https://www.bilibili.com/video/BV1iup7zSE3P/) |

| 神契之约 | [已有同名游戏](https://www.sanguogame.com.cn/game/823018.html) |

**正确标准**：只需避开**知名作品**与**同类作品**，与小众或不同品类的作品重名可以接受（不构成商标冲突，只影响搜索）。按此标准，`守灯人` 一类名字其实可用。

**新三选（均已查重，无游戏占用）**

| 名字 | 判断 |
|---|---|

**唯一真正空白的地带是自造专名**（给这座酒馆起一个世界上只属于它的名字），代价是中文自造名不易记，需要配合世界观铺垫。

## 结论（第三轮修订）：`酒馆` 是别人的品类信号——撤回《流金酒馆》的第一推荐地位

用户追问"酒馆是什么类型游戏"。核实后，**第一轮"A1 酒馆天然是卡牌品类词"的判断是错的**。

**现状：在今天的游戏命名里，`酒馆` 明确指向两个品类，都不是卡牌对战**

| 作品 | 实际品类 |
|---|---|
| [Tavern Keeper](https://www.gamespress.com/ko-KR/Cosy-chaotic-Management-Sim-Tavern-Keeper-Launches-into-Early-Access) | Cozy-chaotic **Management Sim**（经营模拟） |
| [Rekindled: Cozy Tavern Life](https://www.4gamers.com.tw/news/detail/78938/rekindled-cozy-tavern-life-steam-page-released) | 中世纪多人酒馆**经营**，卖点是"不拼翻桌率" |
| [Medieval Tavern Simulator](https://store.steampowered.com/app/4446870/Medieval_Tavern_Simulator/) | 酒馆**模拟经营** |
| [銅鬚酒館](https://www.4gamers.com.tw/news/detail/61447/after-being-kicked-out-of-an-interstellar-dwarf-mining-agency--i-have-taken-up-a-more-grounded-task-of-running-a-tavern) | 矮人酒馆**打工模拟** |
| [众神酒馆 Tavern of Gods](https://steambase.io/games/tavern-of-gods/info) | roguelite **自走棋** |
| [炉石传说·酒馆战棋](http://www.gamelook.com.cn/2019/11/374557/) | **自走棋** |

即：看到"XX酒馆"，玩家预期的是**经营/翻台/雇人**或**自走棋**，而不是"自己组 30 张牌、回合制打首领"。这是**品类误判**，比"品类不自明"更糟——想要经营模拟的玩家会失望，想要卡牌的玩家不会点。

**我错在哪**：把《炉石传说》世界观里的"酒馆"印象当成了品类信号。实际上炉石的中文名是 `炉石`（一个具体物件），"酒馆"在它那里只是**模式名**，而那个模式（酒馆战棋）本身就是自走棋。

**同类的坑**：`牌局` 在中文里指向**棋牌/扑克/麻将**（斗地主那一类），也不是电子卡牌对战的信号。

**修正后的原则**：成功的电子卡牌游戏，名字**基本都不声明自己是卡牌**，而是用一个具体的人 / 地 / 物 / 事件做专名，让封面与商店页去说明品类。

| 作品 | 名字来源 | 是否声明品类 |
|---|---|---|
| 炉石传说 | `炉石`——一个物件 | 否 |
| 杀戮尖塔 | `尖塔`——一个地点 | 否 |
| 月圆之夜 | `月圆之夜`——一个事件 | 否 |
| 邪恶冥刻 | 自造词 | 否 |
| 怪物火车 | 一个物件 | 否 |
| 小丑牌 | 物件 + `牌` | 部分 |
| 万智牌 / 昆特牌 | `牌`（实体 TCG 出身，牌就是产品形态） | 是 |

所以真正要避免的不是"品类不自明"，而是**落进别人已经占住的品类信号**：`酒馆`（经营/自走棋）、`牌局`（棋牌）、`X之战`（页游/王者荣耀）。

**修正后的推荐**（不再以 `酒馆` 作主名品类信号）：

1. **《诸神同辉》**——把 v0.14 现成副题升为主名。事件/状态式命名（同"月圆之夜"），内容 100% 对得上（四神 + 契约 + devotion），气派且不落在任何被占的品类信号上。
2. **《诸神入座》**——「诸神在你桌前落座」。事件式命名，既暗示牌桌又不说"酒馆"，把 v0.14 的降临仪式写进名字。（**未查重**）
3. **《断契》**——取自游戏内真实首领 `断契监誓者`。两字最狠、最有故事钩子（"谁断了契"），品类中性。（**未查重**）

`流金酒馆` / `契约酒馆` / `鎏金酒馆` 降级为"接受品类误判风险时的备选"——若目标是上架商店，不建议；若只是发给朋友、靠截图传播，风险可控。

**证据四：可行路线只剩"专名"**

**自我更正**：第一轮我把"`鎏`难打字"当成减分项，同时又没抓住真问题——**口碑传播是"口播 → 别人去搜"**，`鎏` 需要解释字形，这一步会掉人。`流金` 同音且常用，两个问题一起解决；原字 `鎏金酒馆` 作为备选保留（最美，但口播要说明"鎏金的鎏"）。

## 一、为什么现在这个名字"拗口"

不是字丑，是**它其实是四个名字在同时用**：

| 出现位置 | 当前文案 |
|---|---|
| `<title>`（src/template.html） | 烬域 · 风起之境 — WIND BORNE |
| 顶栏品牌位 / 大厅主标题 | 烬域 / EMBERFALL |
| meta description | 烬域 Emberfall — …原创酒馆奇幻卡牌冒险 |
| README v0.14 | 烬域 · 鎏金酒馆 |
| 旧文档 docs/ANIME_V06.md | 烬域 · 动漫秘境 |
| DISTRIBUTION.json | WIND BORNE / 风起之境 |
| package.json | emberfall-card-game |

具体病灶四条：

1. **一游戏四名**：烬域 / 风起之境 / 鎏金酒馆 / Emberfall / Windborne，玩家记哪个都算对，等于没有名字。
2. **意象打架**：Emberfall 是"火落下来"，风起之境是"风起来"。火与风是两个方向，凑在一起互相削弱。
3. **难念难打**：`鎏`（liú）是生僻字，输入法要翻页；`烬` 也不在常用字表前列。"Emberfall" 连缀辅音，中文口播会变成"恩伯佛尔"。
4. **英文名已被占用**：[Steam 上已有一款 Emberfall](https://store.steampowered.com/app/3301890/Emberfall/)，继续用作正式英文名会直接撞车；`星烬` 也已被 [《星烬 烛耀山海》](https://store.steampowered.com/app/2774370/_/) 使用，不要再选。

## 二、本次命名标准

1. **2–4 字**，且全部是常用字（手机九宫格/拼音首屏就能打出）。
2. **念得顺**：声调有起伏，口播不上头、不打结。
3. **一眼有画面**：听到名字能立刻想象出游戏里真实存在的场景或机制。
4. **一句话说得清**：能直接接住"这是个什么游戏"。
5. **中英双语都能用**：中文名可直译，英文名无连缀辅音。

## 三、候选方案

### 方向 A：场景即招牌（最稳，最像能上架的游戏）

**A1.《余烬酒馆》EMBER TAVERN** ⭐ 主推

> 火还没灭，牌局还没散。

- 四个字全是常用字，声调 2-4-3-3，念着顺；英文两个词、无辅音簇。
- 一次说完游戏的两个核心资产：**余烬**（世界神话、初火、终焰）+ **酒馆**（胡桃木古金 UI 的真实舞台）。
- "酒馆"天然是卡牌游戏品类词，玩家看到名字就知道大概要玩什么，搜索友好。
- 风险：酒馆类名字在品类里不算独家（另有同名酒吧商号），但作为游戏名目前无人使用。

**A2.《烬火酒馆》EMBERFIRE TAVERN**

- A1 的硬朗变体：`烬火`比`余烬`更有燃烧感，适合想让世界显得"还在烧"而不是"快灭了"。
- 声调 4-3-3-3 连仄，念起来比 A1 平一点，是我把它排在 A1 之后的原因。

### 方向 B：钩子即招牌（最好记、最容易传播）

**B1.《借火》BORROWED FLAME** ⭐ 主推

> 向诸神借一缕火，代价写在契约背面。

- 两个字，口语里本来就有的说法（"借个火"），**双关**：既是酒馆里借个火，也是向神借火。
- 与内容严丝合缝：契约牌 = 借神力，`引火学徒`、遗物`初火余烬`、四位神祇都是"火"的持有者。
- 传播力最强的一个：名字短、有反差、别人会追问"借什么火？"
- 风险：不自我说明品类，且两字词搜索定位弱 → **必须配副题**，见第五节。

### 方向 C：史诗即招牌（适合战役与系列化）

**C1.《余火之门》THE EMBER GATE**

> 门后是没烧完的世界。

- 直接取自游戏内首领称号（灰烬监守 · 余火之门），四个常用字，神秘、宏大、有"下一关在哪"的推进感。
- 适合做**战役资料片名**（如《余烬酒馆：余火之门》），独用时更像地牢冒险而非酒馆卡牌，场景感会丢。

### 方向 D：机制即招牌（最贴 v0.14 内容）

**D1.《余烬之契》COVENANT OF EMBERS**

> 神只借你一次，牌得你自己打完。

- 把核心机制（契约 / 诸神同辉）写进标题，和当前版本内容最贴合。
- 风险："之"字偏文气，且"X之Y"式命名在品类中拥挤，辨识度不如 A/B。

### 方向 E：气质即招牌（差异化最大）

**E1.《守灯人》THE LAMPLIGHTER**

> 灯不灭，路就还在。

- 呼应游戏第二条母题：`银灯灵狐`、`守灯巨兽`、`渡魂引路人`、送魂人莫菈、冥月神。
- 文艺、安静、独立游戏气质强，和主流卡牌游戏的命名拉开距离。
- 风险：不像卡牌游戏，传播力弱于 A/B；启用前需单独查重（本次未验证）。

### 补充备选

- **《诸神牌局》THE GODS' TABLE** —「四位神祇，一张酒桌。」把诸神同辉的机制与"牌局"一次说清，品类自明；气质偏宏大，少了酒馆的暖意。
- **《余烬牌局》EMBERS & DEALS** —「牌局散了，火还没灭。」最直白、最不会误解；代价是"牌局"二字略平，记忆点弱于《余烬酒馆》。
- **《余烬王座》EMBER THRONE** —「坐在灰烬上的人，就是王。」史诗感强；但"X王座"在品类里极度拥挤，辨识度需要额外努力。

### 已评估但未入选

**《诸神之门》THE GATES OF THE GODS** —— 顺口（zhū-shén-zhī-mén，1-2-1-2 平顺）、四字常用、气派，与 v0.14 `诸神同辉` 呼应。但有三处硬伤，**不建议做主名**：

1. **丢品类**："门"指向地牢 / 传送门 / 关卡推进，与"酒馆打牌"和现有胡桃木古金视觉互相打架——这正是 `Emberfall` vs `风起之境` 那个错误的翻版。
2. **名不副实**：全游戏 `门` 只出现在一处——首领称号 `灰烬监守·余火之门`。诸神在游戏里的动作是**降临与契约**，不是开门；用这个名字等于凭空造一个游戏里不存在的场景。
3. **红海撞名**：已有同名或近名作品（[诸神之门](https://m.doyo.cn/game/64389.html)、[宿命交锋·诸神之门](https://mshike.it168.com/detail/417076.html)、[Siralim Ultimate: Gate of the Gods](https://wikiwiki.jp/siralim_ult/Gate%20of%20the%20Gods)、Webzen [게이트 오브 게이츠](https://www.gamemeca.com/view.php?gid=1767999)、[神圣之门](https://www.925g.com/game01/308013.html)、[神域之门](https://www.9game.cn/syzm/965595.html)），另有 `诸神黄昏` / `诸神之战` 的强势联想干扰。

**可取之处**：它的仪式感适合当**章节 / 战役副题**，例如 `余烬酒馆：诸神之门`，用来替换 v0.14 的 `诸神同辉`。主名保持清晰，史诗感照留。

## 四、结论与排序

> ⚠️ 本节为第一轮排序，已被上方「第二轮修订」取代：第 1 名《余烬酒馆》**已撤回**（`余烬` 在 79 个卡名中出现 0 次，属旧名残留），现行第一推荐为 **《流金酒馆》**。下表保留作为备选池。

|---|---|---|---|
| — | ~~余烬酒馆 / EMBER TAVERN~~ | **已撤回**：与内容脱节 | — |
| 1 | **流金酒馆 / GILDED TAVERN** | 与 `鎏金酒馆` 同音但全是常用字，贴合胡桃木古金 UI，游戏领域未被占 | 正式主名 |

**我的建议：主名用《流金酒馆》，副题用版本名。** 这样"易记的那部分"永远不变，"变化的那部分"承担内容更新：

## 五、改名落地清单（决策后执行）

显示名改动很便宜，实测成本如下：

1. `src/template.html`：`<title>`、`meta description`、顶栏品牌位（`<strong>烬域</strong><small>EMBERFALL</small>`）、大厅 `.lobby-title`。

3. 重新构建：`python3 build.py`，然后 `node --test tests/*.test.cjs`。
4. 已确认：**没有测试断言依赖显示名**（测试只引用内部全局 `window.Emberfall`），改名不会引发回归。
5. 已确认：**没有把游戏名烘焙进图片素材**（顶栏是 `data-icon="fire"` 图标 + 实时 DOM 文字），因此不需要重做美术。
