# 全员重构 v2：普通人的琥珀战记

2026-10-02。依据 [SETTING_AMBER.md](SETTING_AMBER.md) v1.1，把英雄、首领、对手的造型从"传奇海报"改成"普通人被迫扛起神话"。本文是设计依据和制作台账；每完成一项就更新第六节。

## 一、原则

1. **先是干活的人，再是英雄。** 每人有一份具体的活儿，造型从这份活儿里长出来。
2. **一件日常工具当钩子。** 不发光、不悬浮，缩到 90px 的圆头像里也认得出。
3. **神之琥珀藏在日常物件里。** 吊坠、盾钉、弓把、灯座。琥珀里的生命是远古传奇，持有者是凡人，这就是全剧的反差。
4. **旧、补丁、洗褪色。** 棉、麻、皮、呢；没有丝绸披风、金属浮雕、光环、悬浮物。年龄和体型各不相同。
5. **日常场所、日常光。** 柜台、路口、林边、竖井口；阴天、黄昏、一盏灯。
6. **与卡牌拉开差异。** 卡面是仰拍加神圣逆光；人物立绘是平视三分之二身，脸在上三分之一，柔和光。
7. **一个人一个主色。** 靠衣服而不是发光：娜希拉蓝灰、菲德莉亚赭金、罗温苔绿、利奥尔炭灰加灯火琥珀。

## 二、立绘规格

- 3:4，运行时与卡牌同为 1086×1448。三分之二身（头到大腿中段），脸在上 30%，便于圆头像和全屏展示两种裁切。
- 生图：codex-image（gpt-image-2），`-i` 只给风格参考；提示词必须带"不要光环/不要发光/不要悬浮物/不要仰拍"，末尾带"零烘焙文字"。
- 不同于卡牌的独立 ID 空间：`src/content/portraits.js`（见第六节 P0）。原图存 `assets/portraits/<id>.png`。

## 八、P5：Tripo 3D 与动作方案（2026-10-02 调研）

**动作不用 Tripo 出**：人形角色绑 Mixamo 骨架，驱动它的是项目已有的 89 段 Mixamo 动作（`tools/models/anims`，`SUITES[id]` 指定 idle/attack/hurt/victory）。Tripo 只负责：模型、重拓扑、自动绑定、导出。

**人形角色（娜希拉、菲德莉亚、罗温、利奥尔、铁哨、译者、守根人、根母、纳坦）**
1. 参考图：T 姿势、双手空空、正面、纯灰底（codex 生成，存 `assets/portraits/tpose/<id>.png`，横幅 3:2）。道具另做。
2. Tripo：图生模型（工作区"高精度模型"，H3.1 最高质量，4K 贴图、去光处理、三角面；50 积分，首页快速生成 55）→ 重拓扑（约 1 万四边面）→ 绑定（Mixamo 骨架）→ 导出带骨骼、无动画的 GLB（2K）。
3. 入库：`tools/models/real/<id>.body.glb` → 在 `tools/model_prep.cjs` 的 `REAL` 加条目（无道具写 `{ props: [] }`）→ `node tools/model_prep.cjs <id>` → 在 `tools/model_art.cjs` 的 `FIGURES` 加 `{ right:"held", style:"caster", lit:true, tex:2048 ... }`（`lit:true` 必须）→ `node tools/model_art.cjs` → `python3 build.py`。
4. 代码：`src/presentation/voxel/figures/<id>.js`（`EmberVoxelKit.define`，`cards:["hero:mage"]` 之类；不得留默认 `[id]`）、`config/build.json` 与 `src/template.html` 登记 `VOXEL_FIG_<ID>`、`models.js` 的 `SUITES[id]`，最后在 `portraits.js` 填 `figure`。
5. 道具（灯、弓、盾、放大镜）：单独出图、单独建模，放进 `tools/models/real/props-bN.glb` 道具页（每个角色最多 3 页）。

**兽类（守灯之兽）**：参考图四足纯侧视；Tripo 只到重拓扑，不绑定；导出 FBX 用 `node tools/fbx_to_glb.mjs` 转 GLB → `real/<id>.body.glb`；`tools/beast_prep.cjs` 的 `BEASTS[id]` 绑到已有体素骨架（需先有同 id 的体素角色文件）；`models.js` 的 `BEASTS[id]` 写招牌。

  - 做法：形状给出一个有符号距离函数（负数在内）；先按台面矩形（`HX`×`HZ`，卡牌行永远在它里面）与英雄座台（给每个座台让出一圈）合成最终的距离场，在 256×256 网格上采样，用 marching squares 取零等值线得到多边形，再 ear clipping 三角化成台面、扁平侧壁；距离场同时作为 R16F 纹理（`uPlat`）交给着色器画边缘（舞台聚光衰减、台面光池、各场景的边缘处理：木板端面、警示条、青苔、霜与裂纹、岩缘）。栏杆、植物等沿台缘摆放的东西用 `rimAt(off, s)` / `rimPer(off)`，任何"是否在台上"的判断用 `platSD`。构造耗时约 7–30ms（`EmberArena3D.board.platMs`），只在版式变化时发生。
  - 擂台的 `rr()` 圆角框线不再画在这些场景的台面遮罩里（它们不再有圆角矩形台缘）。
- **页面背景**：`silverblue/backdrop.webp`（弹窗、合约页等页面后的模糊背景）换成 codex 画的矿区夜景（井架、烟囱、锅炉房、远处玻璃温室，无人物）；原来的高奇幻城堡夜景与五张已无引用的旧主题图（mage/paladin/ranger/morla/goddess）退役，主题清单只剩 map/home/backdrop。
- **遗留**：桌面上首领专属的摆设多在远端窄边之外（只看得到横梁、红围巾、风扇的边），手机竖屏看得最完整；琥珀罐、琥珀壳等大块琥珀仍偏平亮。97 张卡牌插画保留旧图不重画（它们是通用幻想风，和新设定冲突的另行处理）。

### Tripo 图片生成（GPT Image 2.5）的用法（2026-10-02，额度恢复前的替代生图）

- 页面：工作区左侧"图片"标签。提示词框 + 参考图（可传多张）+ "生成图片"。每次出 2 张（1152×1536，3:4），**免费额度按张数算**（约 100 张/周期，显示"Free N/100"，N 是已用）；用完每次 40 积分。
