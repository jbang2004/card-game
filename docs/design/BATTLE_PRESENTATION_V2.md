# 战斗表现层 V2：因果、克制、单管线

2026-09-17 立项。取代此前"逐轮加特效"的做法。本文件是实施契约：两条实施线（导演层 / 特效引擎）都以此为准，改动数值先改本文件。

## 1. 为什么重构

审计结论（全文见会话记录，要点如下）：

- **五套渲染后端并存**：EmberFX 自有画布粒子、EmberVFX 画布贴图、EmberFx2 WebGL、EmberFxTop 画布、切入立绘 DOM。桌面、手机、低画质、WebGL 失败各走不同组合，同一张牌在不同设备上是不同的动画。
- **因果错误**：
  - 手机、窄于 1360 的窗口、低画质会退回 EmberVFX，其中流星类法术不看施法者，起点写死为目标 + (-155, -330)，竖屏上落在敌方英雄栏。
  - 手机上英雄锚点取的是整条控制台条的中心，不是英雄卡。
  - 法术落点在无目标时取"整个事件列表里第一个 summon / damage"，不限于本次出牌。
  - 攻击命中点系数 0.77 与突进距离 0.6 不一致。
- **重复**：震屏三套，顿帧三套，命中闪五处，召唤表现六处，传说随从降临与战吼各放一次同学派特效。
- **时序打架**：切入 340ms 对应前摇 300ms；技能 HIT_AT 超过所在拍的 hold，导致数字先出、特效后到；整体压缩不缩放特效与 CSS。
- **装饰冒充状态**：结霜残留像冻结，焦痕像持续伤害，暗紫残留像沉默，白色命中描边像嘲讽环。
- **范围与规则不符**：单体技能的火焰、刀光、落雷盖住相邻两三张卡。

## 2. 原则（必须可测试）

1. **一个原因，一条路径，一个落点。** 每个表现都有明确的施动者 `actor` 和受动者 `targets`，二者只能来自本次动作的事件块（同一 blockId 下的事件）。
   - 路径型表现（弹道、光束、冲撞）必须从 actor 的可见卡面出发，结束于 target 的可见卡面。
   - 英雄一律以英雄卡本身为锚点，不用外层容器。
2. **分量跟后果走。** 同一张牌打 1 点和打 6 点必须看得出差别，差别只由分量档（见 §4）决定，不按卡牌逐张调。
3. **范围跟规则走。** 单体效果的接触画面**逐轴**不超过目标卡包围盒的 1.25 倍（第 3 档）：宽 ≤ 1.25×w，高 ≤ 1.25×h，含 bloom 淡边。只有规则上的群体效果允许覆盖多个单位，且范围逐轴不超过全部目标包围盒的并集外扩 24px。
4. **结果永远可读。** 接触瞬间不得把目标卡整体打白或遮住卡面：命中闪只作用于卡片边缘，最高亮度不超过画面 1.3 倍。伤害数字与血量变化和接触帧同一帧出现（误差不超过 45ms，运行时常量 `EmberTiming.numberSyncMs`）。2026-09-18 起上限由 34ms 放宽到 45ms（≈2.7 帧）：移除分层立绘后，场上不再有逐帧绘制的画布，渲染器每帧的稳定绘制节奏消失，接触数字的定时回调在帧内的相位平均后移约一帧。实测上限 38.8ms，45ms 留约 6ms 余量以免在负载波动下反复抖红；桌面与手机上这约 1 帧的相位后移，45ms 仍在人眼不可辨范围。
5. **画面不冒充状态。** 所有瞬时视觉在接触后 250ms 内完全消失。只有出现对应状态事件时（冻结、沉默、圣盾、护甲等）才允许出现与该状态相关的视觉，而且由状态渲染（卡面 CSS）接管，不由特效残留代替。
6. **动作优先。** 平砍由卡片动作讲故事：抬起、冲出、碰撞、回弹、目标后退。特效只是碰撞点上的点缀。
7. **单管线。** 全平台使用同一套导演层与同一个特效后端（EmberFx2）。
   - WebGL 不可用时，只保留 DOM 动作与数字，不存在第二套画布特效。
   - "减少动态效果"关闭震屏、顿帧、切入与特效层，保留动作的缩短版和数字。
   - "低画质"只降低特效渲染分辨率，不换管线。
8. **大演出稀缺。** 切入立绘、推镜、屏幕级泛光只给传奇随从与英雄。普通随从和普通法术不弹切入、不推镜。

## 3. 架构

```
engine events ──► combat.compile (纯函数，产出 beats)
                      │   每拍携带 actor / targets / tier / blockId / rule{aoe,status}
                      ▼
                director (effects.js，唯一调度者)
                      │   anchors.resolve(ref, snapshot)   唯一锚点函数
                      │   recipes[beat.type](beat, ctx)    表驱动，一种事件一个配方
                      │   timeline.at(ms, fn)              唯一时钟（基于 sequence.origin）
                      │   trace.push({...})                每个表现写一条记录，供测试断言
                      ├──► DOM：卡片动作、受击反应、数字、状态提示、切入立绘
                      └──► EmberFx2：plan() 纯函数取时序；cast()/attack()/contact()/impulse() 画面
```

### 3.1 需要删除的
- `src/presentation/vfx.js`（EmberVFX）与 `src/vfx-assets.js`（约 1.17MB），以及 `config/build.json`、`src/template.html` 中的注册。
- EmberFX 自有画布粒子：`rune / spark / pillar / ring / impact` 的全部粒子类型与绘制分支，`#fx-canvas` 若无其它用途一并删除。
- `src/presentation/fx-top.js`（EmberFxTop）：bladeCross 移植进 fx2 引擎，命中描边改由 fx2 或 DOM 边缘闪实现。
- fx2 引擎内的切入轨、`onCardHit`、各技能自带的 `camera.shakes` / `hitStop` / `flashFrame`（统一由 `impulse` 接管）。
- 重复表现：`signatureCue`、secret 的 cue 与 toast 二选一（保留 cue）、传说随从的降临与战吼二选一（保留降临，战吼只在确有独立效果时出现）、over 拍对英雄的二次受击。
- 审计列出的死代码与死 CSS。

### 3.2 锚点
- `anchors.resolve(ref, snapshot)`，其中 `ref = {side, uid}`。
- 返回舞台坐标下的可见卡面包围盒：`{x, y, w, h, left, top}`。
- 英雄：取英雄卡内框元素（桌面与手机同一个选择器，由导演层集中定义），不取 `#player-hero` / `#enemy-hero` 外层。
- 快照在整个序列开始前取一次。召唤、复生出的新单位在其落位拍之后补录。
- 攻击者冲撞期间，其锚点改为冲撞克隆体的实时位置，冲撞距离与命中点使用同一个常量。
- 取不到锚点时：记一条 `trace` 警告，跳过该路径表现，不回退到任何写死的坐标。

### 3.3 特效引擎接口（EmberFx2）

```js
// 纯函数，不需要 WebGL；导演层用它安排节拍与数字时刻
EmberFx2Engine.plan(kind, { from, targets, tier, aoe })
  // → { hitAt: number[] /* 每个目标的接触时刻，相对 cast */, duration: number }

EmberFx2.cast(kind, { from, targets, tier, tint, tintGrad, aoe, seed })
EmberFx2.attack(family, { from, to, tier, tint, tintGrad, ranged, seed })   // 平砍的点缀与弹道
EmberFx2.contact({ at, tier, tint, tintGrad })        // 无来源技能的通用接触点（例如疲劳、亡语伤害）
EmberFx2.impulse({ at, tier })                        // 震屏、顿帧、局部闪，由导演层在接触时刻调用
EmberFx2.cutin(art, { side })                         // 仅传奇与英雄
EmberFx2.available / EmberFx2.stats
```

- `from`、`targets[i]`、`at` 都是 §3.2 的包围盒，引擎接口一侧以 `{x, y, w, h}` 传入，x/y 为中心点。
- `plan().hitAt` 不含顿帧；导演层在接触时调用 `impulse` 后，同一序列里此后的接触时刻整体后移其返回的 `hitStopMs`。
- 引擎负责把接触画面限制在目标包围盒内（§2 原则 3），并按 §4 的 `contactScale` 缩放。
- `plan()` 返回的 `hitAt` 与引擎实际画面的接触帧一致（误差不超过 1 帧）。
- 群体技能按目标到施法者的距离由近及远排序，逐个错开 `STAGGER` 毫秒。

## 4. 数值表（唯一出处：`src/presentation/timing.js`）

### 4.1 分量档

| 档 | 条件 | contactScale | 震屏 | 顿帧 | 目标后退 | 音量 |
|---|---|---|---|---|---|---|
| 1 | 伤害或治疗 ≤ 2 | 0.80 | 无 | 0 | 6px | 0.75 |
| 2 | 3–5 | 1.00 | 3px / 160ms | 50ms | 10px | 0.9 |
| 3 | ≥ 6，或致死，或英雄受到 ≥ 5 | 1.20 | 6px / 240ms | 90ms | 14px | 1.0 |

- 增益、状态、召唤等没有数值的效果一律为第 1 档。
- 一次动作有多个目标时，每个目标各自定档；震屏与顿帧取其中最高档，只触发一次。
- 震屏只作用于棋盘与特效层，不作用于手牌和 HUD。

### 4.2 时长（毫秒）

| 表现 | 分段 | 合计 |
|---|---|---|
| 随从近战 / 英雄武器平砍 | 抬起 110 → 冲出 150 → 接触（+顿帧）→ 回位 200 | 460 + 顿帧 |
| 随从远程平砍 | 后坐 90 → 弹道按距离 1800px/s，限 90–220 → 接触 | ≤ 310 + 顿帧 |
| 单体弹道法术 | 施法闪 120 → 弹道按距离 1400px/s，限 160–320 → 接触 | ≤ 440 + 顿帧 |
| 单体非弹道法术（沉默、变形、增益） | 施法闪 120 → 连线或光束 140 → 接触 | 260 |
| 群体法术 | 施法闪 120 → 每目标错开 45（最多 5 步）→ 最后一个接触 | ≤ 345 + 顿帧 |
| 治疗 | 同单体弹道，弹道柔和 | ≤ 440 |
| 死亡 | 最后一个接触后 120 → 定格变暗 100 → 溶解 320 → 队列补位 220 | 760 |
| 召唤 | 落位压扁 260；传说额外降临 500 | 260 / 760 |
| 抽牌 | 300 | 300 |
| 回合提示 | 900 | 900 |
| 切入立绘（仅传奇与英雄） | 70 入 / 190 停 / 80 出，前摇相应延长到 340 | +340 |

- 数字、血量变化、受击反应、音效都以 `plan().hitAt` 为准，与画面同帧。
- 敌方回合的动作使用完全相同的配方与时长，只做左右 / 上下镜像。AI 两个动作之间的间隔保持现值。

## 5. 验收

1. **因果测试**：新增 `tests/e2e/presentation-causality.spec.cjs`，读取导演层的 `EmberFX.trace`。桌面 1600×940 与手机 390×844 各跑一遍，覆盖以下矩阵：
   - 施动方：己方 / 敌方。
   - 动作：随从近战、随从远程、英雄武器、单体弹道法术、单体非弹道法术、群体法术、治疗、英雄技能、战吼、亡语伤害、奥秘反制。

   对每条记录断言：
   - 路径起点位于 actor 包围盒内；
   - 终点位于某个 target 包围盒内；
   - actor 与 targets 都属于本次动作块；
   - 数字出现时刻与 `hitAt` 相差不超过 45ms（2026-09-18 由 34ms 放宽，理由见 §2 原则 4）；
   - 单体接触画面逐轴不超过目标包围盒 1.25 倍；
   - 序列结束 250ms 后没有残留节点，特效层绘制数为 0。

   火球从敌方英雄发出这一类错误必须被这个测试抓住。
2. **后端唯一**：仓库内不再存在 EmberVFX、EmberFxTop 与 EmberFX 画布粒子的定义与调用；`index.html` 体积至少减少 1.1MB。
3. **性能**：桌面与手机模拟（390×844、DPR 3、CPU 4 倍降速）下，施法期间 `EmberFx2.stats.jsMs` p95 ≤ 1ms，帧间隔 p95 ≤ 20ms。
4. **回归**：`npm run test:release` 全绿。断言表现层内部实现的旧测试改写为针对 trace 与行为的断言，并在报告中列出每处改写理由。
5. **观感核对**：每类动作输出 60fps 定格视频与真实对局截图，桌面与手机各一份。同一场景桌面与手机的节拍顺序必须一致、时间差不超过 34ms；按距离计算飞行时间的表现（远程平砍、弹道法术）只比较飞行段以外的节拍（发起时刻，以及以接触时刻为起点的后续节拍）。


## 6. R3 三维试点的局部例外（2026-09-18）

本节仅适用于 `src/vfx3/` 接管的喷火与剑击，不改变 EmberFx2 其他技能的 250ms 规则。用户要求对齐《焰·弦·刃》的自然火焰和更有动作感的空中重劈，因此不再将其全部余韵压缩到原点缀型特效时长。

- **原有因果、命中和规则不变。** 在导演层现有 `beat.at` 即启动同一三维实例，利用原有卡牌预备动作时间。`contactAt` 仍由原编译器提供；旧的抬起结束回调不得再次发射。
- **喷火：** 首次接触后最多持续发射 680ms，单个火舌按出生时间自然衰减，整体清理边界为接触后 1450ms；均按原 `timeScale` 缩放。只有原规则的一次伤害，不用闪烁数字暗示额外持续伤害。
- **剑击：** 空中回引、弧线加速挥落、45–70ms 姿态停留、微小阻尼卸力，接触约 280ms 后开始抬起撤出。刃光来自同一刚体剑的历史刃口位置。整体尾部上限为接触后 1120ms，剑本体更早消失。
- **裂地：** 裂缝增长从中心逐段连续展开，保留瞬时暗缝、断层边缘和碎屑；不切割原卡面，不永久改变棋盘，也不暗示地形规则。
- **不额外锁定操作。** 残焰、烟尘和裂纹只在表现层存在；正常取消、切换场景、减少动态依然立即清理。
- **单次攻击的后端互斥。** 三维路径生效时不得再叠加同名旧 EmberFx2 技能。全游戏仍是受控迁移，不宣称已成为单一三维引擎。
- **验收补充：** 检查第一颗火舌在权威接触时刻抵达、其他较快粒子不提前越过、接触处位置与轴向速度连续；检查剑长恒定、命中锚点固定、回拖幂等和实例不重复。实时原速与半速画面均需人工走查。

R3 实际执行范围与限制见 `DELIVERY_VFX3_R3.md`，不得把既有 V2 的完整验收清单误报为本轮全部通过。


## 7. R4 原版火焰移植（2026-09-18，用户确认只移植火焰）

本节替代 §6 喷火专用时序与轨迹条件；剑击、闪电、规则时刻与现有事件关系不变。

- 原《焰·弦·刃》的 `dragon()`/`spark()` 方法、quintic 缓动、PRNG 精度、mode-8 火焰与 mode-9 烟雾着色器保持原实现。新模块只输出特效，不建立龙模型。
- 游戏起手与权威接触区间映射到原版 0.72–1.46 秒；接触后以原版速度继续，仍遵循序列 timeScale。持续发射到原版 3.36 秒，保留各火舌及烟雾寿命，不强行压到 680ms。清理边界改为接触后 4100ms × timeScale。
- 原版空间先经参考观察方向转换，再等比缩放、刚体旋转到卡牌发射点和目标；不沿攻击轴拉长火舌。原版地板焦痕和贴地光不移植，接触专属光不得先于规则接触出现。
- 透明合成适配为先对预乘能量做原版曝光/色调曲线，避免低透明度边缘被反预乘后过度增亮；不更改原版噪声与色带。
- 原版粒子到达练习柱时的拐弯公式保持原样，不再要求已移除 R3 自定义火舌函数的 C1 条件。原版输出在 32 个时间/画质组合下对照 fixture，覆盖每个粒子/薄片/光晕的参数，而非仅比较统计数。
- 不阻塞规则队列、不重复扣血；取消、切场景和减少动态立即清空。未移植原龙模型、骨骼、地板或原演示的其他两招。
- 完整可追溯信息见 `REFERENCE_FLAME_PORT.md` 与根目录 `DELIVERY_VFX3_R4.md`。

### R5 用户指定：屏外垂直天剑

`slash` 的三维分支按新要求由屏幕顶部之外直落卡面，不再沿 actor→target 挥砍，也不再落于目标脚下。权威接触时间和伤害保持原计划；目标仍唯一绑定本次动作。新实现位于 `vfx3/skyfall.js`，120ms 末段加速贯入、定刃、卡面分叉裂纹与短暂碎屑。攻击者仅短后坐，避免同一动作又有整卡冲撞。裂纹不修改原画、不冒充持续状态；在命中后 960ms 内消失，余韵不锁输入。详见 `SKYFALL_CARD_STRIKE.md`。R4 原版火焰与着色器不变。
