# 琥珀手牌

2026-09-28 · 设计稿，实验室原型已完成，未接入游戏。

设定依据：[SETTING_AMBER.md](SETTING_AMBER.md) 第三节、第十一节——每张牌都是一块琥珀，里面封着根战中战死的远古生命、一道咒术或一件兵器；法力是持有者的火种之温；出牌是把琥珀焐热、唤醒里面的生命。

原型：`tools/amber-lab/`（本地起 8012 端口后打开 `/tools/amber-lab/`）。截图：[战场](img/amber-hand-battle.jpg)、[鉴珀图谱](img/amber-hand-tray.jpg)。

## 一、核心想法

手牌不再是一排卡片，而是一条**琥珀带**：英雄斜挎的皮带上扣着一块块琥珀，每块琥珀挂在一枚黄铜温度章下面。

四条视觉通道，各管一件事，互不重叠：

| 通道 | 管什么 | 做法 | 世界观里的理由 |
|---|---|---|---|
| **颜色** | 职业 | 蜜珀（中立）、金珀（圣卫）、绿珀（游侠）、蓝珀（法师，表面泛蓝荧光） | 天然琥珀本来就有这四个品种 |
| **切工与镶嵌** | 稀有度 | 普通：随形原石＋皮绳；稀有：素面蛋面＋银托四爪、蓝宝；史诗：刻面腰棱＋包边、紫晶；传说：雕件＋世界树叶金冠、光晕 | 鉴珀师给琥珀分级；金属和宝石沿用现有卡框的稀有度色（灰、蓝、紫、金） |
| **外形** | 类型 | 随从：泪滴；法术：圆珠；武器：六棱晶 | 封住的是什么，琥珀就长成什么样 |
| **光** | 能不能出 | 焐得热的琥珀从里面亮起来，温度章变成烧红的黄铜；焐不热的琥珀偏暗偏冷，温度章是铁色 | 法力是火种之温 |

文字仍是实时 DOM（`AGENTS.md` 的约束）：费用在温度章上，名字写在**鉴定签**上（藏家给每块琥珀系的纸签），攻击在黄铜六角钉上，生命在一滴血珀里，武器耐久在盾形钉上。

## 二、交互

| 时刻 | 表现 | 对应规则 |
|---|---|---|
| 静止 | 琥珀垂直挂在皮带上，只露出温度章、琥珀上半和鉴定签 | 手牌 |
| 悬停 / 长按 | 琥珀升起放大，跟着指针转动：折射、腰棱火彩、太阳花闪烁，里面的生命微微呼吸；鉴定签垂到下方，展开完整规则 | 读牌 |
| 相邻琥珀 | 像钟摆一样轻轻晃（阻尼摆，挂点是温度章） | —— |
| 新回合 | 一道火光沿皮带从左往右走，经过哪块能出的琥珀，哪块就亮起来 | 法力回复 |
| 抽牌 | 一块没开窗的原石从琥珀匣飞到皮带上，外皮从中心往外磨掉，开出一扇窗，镶嵌最后扣上 | 抽牌 = 开窗 |
| 出牌 | 琥珀飞到场中，越烧越亮，裂纹一道道透出光，然后碎成琥珀碎片和树脂滴，里面的生命走出来 | 唤醒 |
| 火种不够 | 琥珀抖一下，提示"火种不够暖" | 法力不足 |
| 对手的手牌 | 一排没开窗的**原石**：看得见有几块，看不见里面封着什么。黑玉之界的敌人是黑玉原石 | 隐藏信息 |

"开窗"是琥珀行里的真实术语：在原石上磨出一小块光面，才能看见里面。

## 三、渲染

- **一个 WebGL2 上下文画所有琥珀**（`EmberAmber.paint(canvas, spec, state)`）：静止的琥珀按"冷 / 热"两种状态各烘焙一次到自己的 2D 画布，切换时交叉淡入；拿在手里的那一块每帧重画。
- 着色器：折射率 1.54 的穹面把插画折射到一定深度（插画本身再用现有的浮雕深度图做视差），按琥珀品种做比尔-朗伯吸收（越靠边越厚、越红），色散、边缘光、焦散、反射只取柔光箱；随机但稳定（按卡牌 ID 取种子）的气泡、太阳花、流纹；原石外皮、开窗边缘的火光、唤醒的裂纹；皮绳、银托、包边、金冠和宝石全部在着色器里程序化生成。
- **不需要任何新图片**：用现有卡图（336×448）、浮雕高度图和摄影棚环境图。Artifact 体积几乎不变（渲染器约 25 KB 脚本）。

## 四、接入计划

1. `tools/amber-lab/amber.js` 移到 `src/presentation/amber.js`，登记进 `config/build.json`；纹理来源换成 `EmberArt.card(c)` 与 `card-relief` 相同的资源解析。
2. 手牌：`#hand .hand-card` 按钮保留（点选、拖动、无障碍标签不变），里面的 `cardHTML` 换成琥珀结构；`EmberHand.metrics` 改为琥珀尺寸与挂点弧线；皮带画在手牌层后面。
3. 拿起：`#hand-card-lift` 改为活画琥珀，取代手牌里的浮雕卡面（其他场景的浮雕不动）。
4. 拖动：以抓取点为支点的钟摆；放到战场上时先播 0.5 秒的唤醒，再接现有的召唤动画和 3D 角色登场。
5. 对手手牌 `#enemy-hand .card-back` 换成原石；按对手阵营选琥珀或黑玉。
6. 手机：竖屏手牌坞里琥珀缩到约 92 px 宽，皮带拉直成水平；点按拿起、长按读签，沿用现有流程。
7. 降级：没有 WebGL2 时用 CSS 版（椭圆裁切＋品种色叠加）；减少动效时不做活画、不晃、不播碎裂。
8. 测试：`hand-reading`、`hand-drag`、`card-reading` 等 e2e 依赖 `.card-title` / `.card-copy` 选择器，要同步改；新增琥珀烘焙缓存与状态切换的单元测试。

## 五、待定

1. 整体方向（皮带上的琥珀）是否采用。
2. 皮带要不要（原型里可开关）。
3. 静止时只显示名字，规则文字在悬停或长按时展开：是否接受。
4. 范围：只改战场手牌，还是连同起手换牌、发现、奖励三选一一起改成琥珀（收藏页建议保留卡面，便于大量阅读）。
