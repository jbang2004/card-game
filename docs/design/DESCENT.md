# 下井（The Descent）— 玩法与叙事结构

2026-10-03。取代"每层二选一对手"的地下城远征。对战规则、AI、3D 战场不变；变的是战斗之间的一切：在哪里、遇到谁、为什么打、打完做什么、失败留下什么。世界观仍以 [SETTING_AMBER.md](SETTING_AMBER.md) 为准，本文件只写流程与数据约定。

**2026-10-04 故事重构**（世界观 v1.2）：四位持珀者在路上相遇、在根海会合；教会的四封信；纳坦的传声管；封根只封住一边，同一位持珀者的第二趟下井是另一套文字（`again`），走到第九层。见下文"两趟故事"。

设计取向：**结构学杀戮尖塔（可见的分岔地图、节点类型、歇脚二选一），战斗体量学炉石地下城冒险（每战满血、全程约 8–12 场），叙事学哈迪斯（失败也推进，角色记得上一趟）。**

## 一趟下井

```
首页「下井」→ 选持珀者 → 阿玛拉送行 → 第一幕开场 → 地图
   地图上选一处 → 遭遇 / 见闻 / 礼拜堂 / 吊篮 / 遗藏 → 回到地图 → … → 守关者 → 下一幕
终幕击败纳坦 = 封根（通关）。同一位持珀者封过根之后再下井，会继续走到第九层（黑玉之界，真结局）。
```

| 幕 | 地点 | 行 | 守关者 | 战斗 tier |
|---|---|---|---|---|
| 第一幕 | 联邦矿区 | 遭遇 ×3 → 遭遇/强敌 → 见闻/吊篮 → 礼拜堂/见闻 → 守关 | 铁哨 或 第七号掘进机 | 1 / 2 / 3 |
| 第二幕 | 古代地层 | 遭遇/见闻 → 强敌/见闻/遗藏 → 遭遇/强敌/见闻 → 礼拜堂/吊篮 → 守关 | 守根人 | 4 / 5 |
| 第三幕 | 神话战场 | 遭遇/见闻 → 强敌/见闻/遗藏 → **镜影**（固定）→ 礼拜堂/吊篮 → 守关 | 艾达 | 6 / 7 |
| 终幕 | 根海 | **会合**（固定）→ 工作台上的日记（固定）→ 礼拜堂/吊篮 → 守关 | 点火者·纳坦 | 8 |
| 第九层 | 黑玉之界 | 见闻 → 守关 | 另一边的伊芙 | 9 |

- 每幕的地图进幕时按种子生成：每行的地点种类来自模板并洗牌，路线保证处处可达、不交叉。一行可以用 `event` 指定它的见闻（终幕的两行）。
- **火种**（3 格）是唯一的风险货币：每战满血；输一场熄一格，对手仍在原地，可以再战；熄尽则被神之琥珀拉回地面，这一趟结束。只有礼拜堂"添火"和部分见闻/处置能回火种。
- 输掉的那一趟会把最好的几张牌（非起始牌）留在井下，落到**典当人**手里：下一趟他带着这些牌出现在第一幕，击败后可赎回一张。

## 两趟故事

每位持珀者有自己的两趟（`EmberChronicle.carry(c, heroId)`：这位封过根，`run.epilogue` 才为真）。

| | 第一趟：封根 | 第二趟：镜中人 |
|---|---|---|
| 幕开场 | 传声管里是纳坦，对这一位持珀者说话（`acts.*.voice`：一句通用、一句专属） | 传声管里只有敲门声，一幕比一幕近（`acts.*.again`） |
| 第一幕的誓言 | `heroes.*.vow` | `heroes.*.again` |
| 另外三位持珀者 | 泵房的岔口（第一幕）、拆开的信（第二幕）、根须下的三盏灯（第三幕），都在见闻池里；终幕第一处固定是会合：四封信、三块神之琥珀交到手里 | 同样的地点，`again` 的文字：没有信了；门外的三盏灯 |
| 守根人 / 艾达 / 纳坦 | 拦路 / 要把父亲带回来 / 等钥匙 | 重新站起来（"只关一边，守不住"）/ 守着门的图纸 / 在门里拆螺栓 |
| 结局 | `endings.seal`：纳坦替主角留在门里；每位主角一句收尾 | `endings.mirror`：两人各守门的一面，炉母醒来，琥珀里的人自己选；每位主角一句收尾 |

见闻里"陪谁"的选项用 `needs.not`（英雄 id）：这位持珀者自己的那一项不显示，所以每个人看到的都是另外三位。`data.js` 保证每个见闻对每位英雄至少剩两项。只有文字因人而异的见闻用 `vs`（如"拆开的信"：平时是娜希拉拆的，主角是娜希拉时换成罗温）。

战斗内台词（`barks.js`）读取存档里的 `epilogue` 来决定用哪一套。

## 遭遇三拍

1. **战前**（遭遇页）：地点、对手为什么拦你、他的第一句话、规则（生命/牌库/技能/半血）。部分对手有不必动手的路：把死亡名单递给红围巾、向估价人付过路费、守林人对早醒者放下弓、提灯人对守灯之兽举灯。
2. **战中**（`presentation/barks.js`）：开战一句、半血一句，在敌方英雄旁的气泡里；艾达对菲德莉亚、纳坦对四位主角各有专属台词。
3. **战后**：倒下的那句话与赏金；具名对手还要你做一个决定——**拿走**（他的琥珀、信物、马克）还是**放手**（火种、祝福、放下一张牌）。然后三选一卡包（可以都不拿），守关者另给一件宝物。

主题"保存与放手"落在机制上：拿牌是保存，删牌叫"放下/归还"。v1.2 给了它字面的含义：琥珀封住的是一个人的最后一口气，把琥珀还给礼拜堂石盆里的树脂，他才走得完那一步。

## 地点

| 地点 | 做什么 |
|---|---|
| 遭遇 | 小对手（预设卡组削弱版，或拾珀人这类小人物）。赢了有马克与卡包 |
| 强敌 | 具名对手，赏金更高，战后有处置选择 |
| 镜影 | 持珀者在另一边的倒影（每位英雄各一） |
| 见闻 | 一屏字、一张图、两三个选项，不战斗 |
| 礼拜堂 | 三选一：添火（+1）、归还（免费放下至多两张牌）、守夜（下一战 6 护甲） |
| 铜壶吊篮 | 阿玛拉从井口放下来的篮子：三张牌、一件信物、付费放下一张牌，附她的一张字条 |
| 遗藏 | 宝物三选一（信物 / 神契 / 传说或高费史诗） |

## 元进度（`rules/chronicle.js`，存储键 `emberfall.chronicle.v1`）

- 《根海手札》：25 页，来自首次击败某些对手、某些见闻选项、过幕与结局。找到即永久保留，在导航「根海手札」里翻看。v1.2 新增四页：估价册的凡例（估价人）、最后一口气（早醒者 / 裂开的琥珀）、四封信（拆开的信 / 根海会合）、炉母的火（走完第九层）。
- 阿玛拉在送行和柜台说的话取决于上一趟：倒在哪一幕、倒在谁面前、是否封过根、是否到过另一边。
- 某位持珀者封根一次后，他的下一趟会继续到第九层；通关两次或到过另一边后，解锁阿玛拉自己的那一页。

## 数据与代码

| 文件 | 内容 |
|---|---|
| `src/content/dungeon.js` | 幕、每行的地点模板、对手池、tier 强度、价格、卡包主题 |
| `src/content/story.js` | 所有文字：幕开场与传声管、每个对手的遭遇/台词/处置、小对手、见闻、礼拜堂、吊篮字条、阿玛拉、手札页、结局，以及第二趟的 `again`。选项的 `needs` / `effects` 也在这里 |
| `src/content/story-art.js` | 场景、见闻插画、新信物的图（`art/story/`、`art/ui/relics-v3/`） |
| `src/rules/run.js` | 一趟下井的状态与每一步（纯函数、带种子）。`create → begin → travel → engage → resolve → choose/pickCard/rest/…` |
| `src/rules/chronicle.js` | 元进度：`carry`、`absorb`、`close`、`greeting` |
| `src/application/screens/run.js` | 所有页面；`src/presentation/skins/slate/descent.css` 是它们的样式（外壳仍是 `run.css`） |
| `src/presentation/barks.js` | 战斗内台词气泡 |

`EmberRun.telling(data, run, foe)` 与 `EmberRun.eventOf(data, run, id)` 给出"这一趟、这位持珀者"遇到的对手与见闻（叠上 `vs` 与 `again`）；界面和台词只通过它们取文字。

选项效果词表（`story.js` 顶部注释）：`gold` `ember` `card` `cards` `trophy` `relic` `boon` `forget` `copy` `redeem` `flag` `page` `gamble`。新增一个见闻只需在 `story.js` 写一条、在 `dungeon.js` 把 id 放进某一幕的 `events`、在 `story-art.js` 登记一张图；`data.js` 会在构建时校验引用。

信物（遗物）与祝福都是 `campaign.js` 的 `relics`：`boon: true` 的只在下一场战斗生效、不会作为宝物出现，图借用 `like` 指向的信物。`bounty` 是下井层面的效果（每场胜利多得马克）。

对手没有写剧本也合法（`content-model` 的"只加内容"测试依赖这一点）：它会无言地出现和倒下。

## 平衡

`node tools/playtest-run.cjs`（双方同一搜索策略，稳健路线）。2026-10-03、每位英雄 8 趟：32 趟通关 24 趟（75%），圣卫 8/8、提灯人 4/8；多数失败发生在第一、二幕的守关者前。这不是真人通关率；同 AI 对打时，成型的牌组加信物明显强于对手，后三幕偏易。后续若要更难，优先给守关者加"意图预告"式的大招，而不是继续堆血量。
